# 10 — ABMP12 内部结构验证

对 P0 的 9 个现有 `.b` 研究副本进行本地解析，没有扩大提取游戏范围。继续复用固定 commit `531694715df21a9940578f4319d246ac8aa794de` 的 qlie-unpack，而不是另写 ABMP 格式算法。调用前校验源码摘要。

适配层在独立进程临时接入 reader、资源回调与名称读取，记录标签、来源范围、未知参数范围，并在解压前限制声明输出大小；调用结束恢复模块函数，不修改上游文件。不调用上游文件输出或运行功能。

## 实际结果

- 9 个顶层容器全部完成边界解析，发现 8 个嵌套容器，合计 17 个容器。
- 共 48 个成员；其中 17 个采用 BPE 压缩，已成功有界解压。
- 19 个 PNG 和 3 个 JPEG 实际解码成功，记录尺寸、模式和 RGBA 像素摘要，没有导出或展示图片。
- 8 个成员自身是嵌套 ABMP，已进入上述统计；18 个成员的解码后载体仍为 Unknown。
- 保存 98 段未解释参数范围，共 3,633 字节，只保存长度、offset 和摘要，不解释动画含义。

观察到的标签及次数包括：abdata13（14）、abdata14（3）、abimage10（17）、abimgdat13（2）、abimgdat14（33）、abimgdat15（11）、absound10（17）、absnddat11（14）、absnddat12（3）。标签出现不等于其声明的每个 slot 都有实际 payload，因此不能把标签数直接当图像或声音数。

`abimgdat15` / `absnddat12` 的已读取版本字段在本样本中为 1；适配层保留该值和位置，不为其他值臆造语义。图片模式含 RGB/RGBA，样本尺寸包括 1280×720、1024×576、256×1024 和若干小图。没有在这些样本中观察到 IMOAVI；不能推断其他游戏资源也没有。

## 证据与未知项

[上游 Python abmp.py](https://github.com/rafi441/qlie-unpack/blob/531694715df21a9940578f4319d246ac8aa794de/qlie_unpacker/abmp.py) 的资源回调负责成员解压与格式转换，部分参数只 skip。独立查阅的 [msg-tool abmp10.rs](https://github.com/lifegpc/msg-tool/blob/0356bb93be7c1f5b11ec22864919200cf7455e33/src/scripts/qlie/image/abmp10.rs) 同样把 AbData 的载体和部分 param 保存为字节数组；相关代码不足以证明图层、关键帧、时间、模型或事件语义。

本轮只对 Python 容器路径做了实际调用；没有声称运行了 Rust 的 ABMP 解码器，P0 的 Rust 构建仅开启 qlie 文本功能。两个项目源码相似也不等于两份独立实测 oracle。

`raw_bytes_reference` 的 offset **相对于当前容器**，不是直接相对于 PACK。嵌套或压缩成员通过 parent 原始范围、解压后摘要和容器链定位；不能把这些 offset 直接相加当成原始文件位置。未知段同样能够定位，没有静默丢弃。

容器解析 verified 仅表示受支持的区段边界和选定成员解码成功。Unknown 成员、参数意义、动画执行顺序和原引擎画面/时间一致性仍不支持；没有制作动画播放器。

## 安全限制与重现

单成员最多 16 MiB，每个工作进程累计解码最多 64 MiB、4,096 个成员、嵌套深度小于 4；CPU 20 秒、墙上时间 25 秒。当前最大实测嵌套为一层。内存没有可靠硬 RSS 限制，继续在报告中标为 unsupported。未知标签、截断、超限均生成带位置的错误和已解析部分。

原容器的 PNG 签名分别在 offset 1053 和 2960。IHDR 表明两图均为 8 位 RGBA，尺寸分别为 1280 × 160 和 300 × 50。PNG 签名和解码成员中的标签位置为 `verified`。六处图层记录与两张贴图的绑定、绘制顺序、变换和混合方式仍为 `not_tested`。上游成员解码器能够提供这段数据，现有运行时仍只使用对话框静态底图。

原版主程序的静态分派进一步验证了两种图层块宽度。UTF-16 标签 `ablayer21` 位于 VA `0x58f398`，由 `0x58f13b` 引用。命中后 `0x58f14b` 调用读取器 `0x5928e8`，其中 `0x592956` 按计数乘以 `0x1b8`（440）后在 `0x592964` 读取。标签 `ablayer18` 位于 VA `0x58f3d8`，由 `0x58f19b` 引用。命中后 `0x58f1ab` 调用读取器 `0x592724`，其中 `0x5927ab–0x5927bc` 按单字节计数乘以 `0xa2`（162）后读取，并在 `0x5927dd` 调用转换函数 `0x591cc0`。块宽度及版本分派为 `verified`。块首字段在六份真实资源的 83 条图层内严格递增，作为时间字段的解释仍为 `inferred`，需追踪转换结果和播放时的读取方。

原版键值文本导出器以 `0x58fde3–0x58fdef` 定位 440 字节记录，并在 `0x58fe4c–0x58fe56` 把块内 offset 0 的整数输出到 `time=`（字符串 VA `0x590ad4`）。旧格式转换在 `0x591e13–0x591e15` 原样复制该字段，因此两种块的字段身份均为 `verified`。时间单位和播放插值仍为 `not_tested`。同一导出器在 `0x58ffa3–0x58ffc4` 把 offset 0x1c、0x20 输出为 `imagenomode`，在 `0x58ffe9–0x59000a` 把 offset 0x24、0x28 输出为 `imageno`。这些名称的对应关系已核验，具体模式值及其贴图解析规则仍需查播放端。

播放路径在 `0x58c07c`、`0x58c096` 读取不同关键帧的第一路 `imageno`，在 `0x58c0ba`、`0x58c0d4` 读取第二路。两路分别传给同一求值函数 `0x58a93c`，结果写入输出记录的 offset `0x07` 和 `0x0b`（`0x58c0aa`、`0x58c0e8`）。另一分支从更多关键帧读取同一字段，再调用同一函数（`0x58c0f0–0x58c15d`）。此处核验了编号会在播放时求值；输出到实际纹理的映射、`imagenomode` 各值以及脚本绑定是否参与这一流程仍待验证。

绘制端在 `0x5844dd–0x5844fc` 分别将输出记录 offset `0x07`、`0x0b` 的两路编号传给 `0x584284`，再把返回值保存到 `0xa4`、`0xa8`。查找函数在 `0x5842af–0x5842cc` 拒绝负编号和达到表长的编号，对有效编号在 `0x5842e4–0x5842e7` 直接索引图像表。表内条目仍经过后续类型和替换处理（从 `0x584309` 起）。两路共享有界的零基表索引这一步为 `verified`，尚需核对该表的构建顺序、命名替换和输出混合，才可把容器成员顺序用于渲染。

图像查找函数 `0x584284` 有两类已定位的替换入口。条目属性名 `link`（VA `0x584478`）在 `0x584322–0x584366` 读取 0 至 3 的编号，从对象 `+0x28` 的表选取非空图像，再重新取得图像句柄。属性 `messurface`（VA `0x584490`）在 `0x584369–0x584391` 检查宿主 `+0x489` 的启用标志并取 `+0x434` 的句柄。另有同一标志和句柄的分支，在 `0x5843d1–0x58443f` 检查以 `*m` 或 `*M` 开头的名称，并搜索 `*messurface`（VA `0x5844b4`）。这些静态条件为 `verified`。仍需确定名称对象来源及消息表面生成路径，才能判断真实对话框在哪些帧使用动态表面。

动态表面的来源可以追到消息对象。消息对象在 `0x677f42–0x677f49` 构造并保存 `+0xdb0` 的对象引用；`0x677fac–0x677fc3` 将该引用注册到其背景对象 `+0x334` 所指对象的 `+0x434`，并打开 `+0x489` 标志。背景重建路径 `0x678a39–0x678a5b` 重复注册同一引用。这证实替换路径能收到消息对象持有的动态表面，也说明两张容器 PNG 单独叠加不足以复原该路径。像素内容、采样矩形以及文字相对动画层的坐标仍待核对。

消息表面调整入口 `0x67bbb0` 在 `0x67bc00–0x67bc0c` 拒绝逆序边界，在 `0x67bc12–0x67bc39` 将每轴跨度限制在 4096。它在 `0x67bc5a–0x67bca2` 以每轴跨度与 4 的较大值，再加两倍该轴边距，调整消息对象 `+0xdb0` 的表面。原生核心已按该入口修正消息逻辑矩形，表面分配公式为 `verified` 的静态证据，ABMP 采样仍待接入。

文字像素写入消息表面之前，`0x67853d–0x67855c` 分别把两轴边距加到输入坐标，再在 `0x67857c` 写入 `+0xdb0` 的表面。另一分支 `0x678583–0x6785c3` 还使用表面尺寸反算一轴，仍计入两轴边距。这个偏移属于表面内部坐标。直接绘制到画布的现有预览缺少配对的表面采样步骤，不能单独把这两个值当作画布偏移。

新版关键帧的两组源矩形分别位于块内 `0x50–0x5c` 和 `0x60–0x6c`，导出器在 `0x590181–0x5901cc`、`0x590202–0x59024d` 将其输出为 `srcarea1`、`srcarea2`。探针已读取这两组字段，真实对话框的 24 个关键帧均为两组全零。绘制端对特定类型的两路矩形调用 `0x584164`（调用点 `0x584572`、`0x58458b`），若四值全零且纹理存在，填入从纹理读取的宽高。这证实有全纹理采样分支，但尚未核对对话框每帧进入此分支前的矩形求值。

两份对话框变体各有 24 条新版关键帧。探针读取的块内 `type`（offset 4）和 `blend`（offset 8）由导出器 `0x58fe7c–0x58feb8` 命名。每份资源中，两个动作的 Frame 和 Message 层各只有首帧记录 type 4，其余 20 条记录为 0，所有 blend 值为 0。绘制端 `0x584502–0x58455e` 以已经求值的类型分派，类型 4 会进入源矩形补全。文件中后续关键帧的零值是否沿用首帧类型，仍需跟踪求值端，不能据此把后续帧当作隐藏。

关键帧选择器 `0x58dc9c` 在 `0x58dcb9–0x58dcd3` 用请求时间与块首时间逐项比较，取不晚于请求时间的最后一个索引。求值器在 `0x58d67e–0x58d685` 接收该索引，在 `0x58d811–0x58d822` 直接复制所选关键帧 offset 4 的低字节为当前绘制类型，未在该步骤对零值执行向前查找。相邻时间差的比值在 `0x58d739–0x58d796` 计算并夹在 0 到 1 之间。这验证了类型的离散取值与数值求值时使用的段内比例。类型 0 的绘制效果和对话框动作触发时机仍待确定。

绘制循环在 `0x587a24–0x587a2c` 求值当前层，输出记录位于栈帧 `-0x192`。随后 `0x587a32–0x587a39` 直接检查其 offset 4 的类型字节，零值跳到 `0x5880af`，递增层索引并处理下一层。因此求值为 0 的层不会进入绘制分派（`verified`）。对于这两份对话框资源，后续零类型的关键帧不能作为持续绘制贴图的依据。持续画面是否来自其他宿主绘制步骤或前一层操作仍待核对。

消息对象还有一条运行时构建路径。重建函数 `0x678a30` 在 `0x678a74–0x678a84` 取图像表第 0 项并向 `0x5989d8` 传入名称 `*MesSurface`（VA `0x678ae8`），随后在 `0x678a89–0x678a9f` 调用 `0x593f28` 和 `0x580490`。最后在 `0x678aa4–0x678ad0` 沿动作 0、图层 0 找到数据块，将两轴传入值写入 offset `0x84`、`0x88`。因此需要区分消息对象初始化生成的动作与资源内记录的开合动作，不能仅以文件里的零类型帧推断消息显示周期。

默认消息层生成器 `0x580490` 在 `0x5804ec–0x58054a` 把首关键帧时间及第一路源矩形置零，设置类型 2、混合值 1。它在 `0x5805c9–0x5805e2` 追加时间 1000 的关键帧，并在 `0x580661–0x58068f` 读取第 0 项图像的宽高写入动作容器。绘制分派表 `0x587de8` 的类型 2 项指向 `0x587e63`，再调用 `0x585390`。因此默认消息层走类型 2，和对话框资源内开合动作的类型 4 路径可分别实现。混合值 1 的具体像素运算和两条路径的切换时机仍待核对。

默认消息层的混合值会经二次编号映射。类型 2 绘制函数 `0x585390` 在 `0x58548f–0x5854a1` 读取输出记录 offset 5 并调用 `0x57e320 → 0x57e284`。后者先取低 7 位，再用跳表 `0x57e299` 分派。输入 1 走 `0x57e2da` 返回后端值 3，输入 0 走 `0x57e2d5` 返回后端值 1。类型 2 随后将该结果作为参数传给 `0x55b2e4`。这验证了格式编号和后端编号的映射，后端值 3 的具体像素运算仍待核对。

默认消息层的后端混合编号随绘制记录进入队列。类型 2 将映射后的值压栈（`0x58549c–0x5854a1`），`0x55b334` 从参数槽 `+0x20` 取出并传给 `0x559de8`。该值由 `0x559dee` 保存，经 `0x559a01–0x559a12` 传到 `0x559eb8`，再由 `0x559f0d–0x559f11` 写入绘制记录 offset 4。调用点 `0x559fad` 把记录交给 `0x55be20`，后者进入 `0x553f78`。这一路径证明值 3 被保留到提交绘制记录，尚未证明它对应的源与目标混合因子。

队列消费路径 `0x558b50–0x558b5d` 取出记录并调用 `0x557db4`。该函数在 `0x557e08` 和 `0x557e8f` 读取 offset 4 的混合编号。两张分派表（`0x557e23`、`0x557ea6`）均将编号 1、2、3 归入同一分支，后续结合 alpha 等条件决定返回分类。此处是记录分类，不能用该分组推断三个编号的混合因子相同。

队列执行器在 `0x5570d3–0x5570e7` 同时读取绘制记录的混合编号（offset 4）、另一参数（offset 8）和命令类型（offset 0），以命令类型选择参数打包路径。类型 0 的表项指向 `0x557136`，其中 `0x5571a5`、`0x55721c` 将打包结果交给参数提供的回调。这里的命令类型 0 属于后端记录，与前述 ABMP 图层类型 0 属于不同字段。下一步需从回调提供方确认实际混合因子。

执行器入口 `0x557010` 的调用包装在 `0x557934`。包装读取上下文 offset `0x1e` 并将它作为后端回调参数传入，执行器在 `0x5571a5` 间接调用。调用包装的一条上游路径在 `0x558d3b–0x558d44` 从当前目标对象 offset 8 填入上下文 offset `0x0c`。需要按实际分支追踪上下文 offset `0x1e` 的初始化，不能将目标对象句柄或上下文的另一字段误作回调。

后端命令类型 0 还有直接提交路径。若记录 offset `0x0c` 为零且上下文未启用回调分支，`0x557136–0x557171` 将混合编号连同绘制参数传给 `0x54bc18`。该函数在 `0x54bc86–0x54bc8c` 读取编号并调用 `0x54fe14`，随后把返回值传入 `0x534cb0`（调用点 `0x54bca4`）。因此可沿直接路径查状态映射，无需先还原间接回调。此证据不涵盖走另一分支的命令。

直接路径的编号转换已核验。`0x54fe14` 以低 7 位索引 `0x54fe25` 的跳表。后端编号 1 和 3 分别转到 `0x54fe6c` 和 `0x54fe72`，两处均返回低字节 1。因此在这条路径上，文件混合值 0、1 虽然先映射到不同后端编号，传入 `0x534cb0` 的低层模式一致。该模式在 `0x534d51–0x534d58`、`0x534d95–0x534d9c` 分别传入 `0x535258` 和 `0x536df0`。此结论仅限直接分支，尚未核验低层模式 1 的像素公式。

低层模式 1 经 `0x536df0 → 0x5332b8` 的分派返回空的额外像素回调（表项 1 指向 `0x53338e`，而入口已清零 EDX）。直接路径的默认像素函数 `0x53a4e8` 在无回调时，`0x53a585–0x53a5d5` 读取目标像素，从源高位分量提取权重，并逐通道计算 `目标 + ((源 − 目标) × 权重 >> 7)`，最后无符号饱和写回。此处核验的是默认函数的一条分支；源预处理、量化常量及替代像素函数仍需对照，不能直接宣称与系统画布逐像素等价。

默认单像素分支的权重边界可精确复算。VA `0x6f7ecc` 的常量是四个 16 位的 1。结合 `0x53a598–0x53a5b2` 的加法与右移，对预处理后位于第四个 16 位槽的 8 位值 `a`，权重为 `(a + 1) >> 1`。因而 `a=0` 时保留目标，`a=255` 时以源替换目标，`a=127` 与 `128` 都得到权重 64。若额外掩码存在，`0x53a535–0x53a56b` 会先把源高字节和掩码高字节相乘再右移 8 位。这些结论限于该像素分支，不代表所有滤镜及其他绘制模式。

开场回放定位到 `textanimation.b` 和窗口 `animation.b` 的动作未绘制。对现有真实副本的有界探测显示，两者各只有一项 JPEG，且开场相关动作包含旧格式类型 16、4、17。原版普通绘制分派表 `0x587de8` 的类型 16、17 分别指向 `0x588028`、`0x588046`。类型 16 的 `0x586518–0x58659d` 读取位置、混合等求值字段，经 `0x55b580` 提交后端命令 14。类型 17 的 `0x5864d0–0x586510` 传递两个浮点参数，经 `0x55b860` 提交后端命令 15。这两条提交路径没有传入图像查找返回的纹理句柄。分派及命令编号为 `verified`，命令对绘制目标和后续图层的作用仍为 `not_tested`。

命令 14、15 在通用队列执行器 `0x557010` 的跳表均指向循环尾部 `0x557877`，实际处理位于另一条队列路径 `0x558594`。命令 14 调用 `0x55bc2c`，在容量允许时压入一份 176 字节的绘制状态，前三组坐标分量与父状态相加，后三组缩放分量与父状态相乘（`0x55bc6f–0x55bca7`）。命令 15 调用 `0x55bc20`，状态深度大于零时减一。命令 13 调用 `0x55bbb8`，复位深度并初始化基底状态。这些栈操作是 `verified` 的静态结果。仍需核对中间类型 4 命令如何消费栈顶，以及旋转、颜色和混合如何映射到原生画布。

类型 4 在普通分派无替代目标时经 `0x587ec3 → 0x585660 → 0x55b2e4` 提交纹理绘制。在状态处理路径，普通绘制记录经 `0x5585ed → 0x55b968` 应用当前栈顶。深度为零时保持记录原样。深度非零时，`0x55b986–0x55b9c6` 先对四个顶点逐轴加上栈顶偏移，之后才处理旋转和缩放。缩放围绕目标宽高的一半执行，单轴公式为 `center + (position - center) * scale`（`0x55babe–0x55bb35`）。`0x55bb65–0x55bb7a` 将记录与栈顶的 8 位透明度相乘后整数除以 255。栈顶混合值不为 1 或采样值不为 0 时，分别覆盖记录中的对应字段（`0x55bb80–0x55bb92`）。这些步骤为 `verified` 的静态路径。将其应用到真实 ABMP 还需把旧格式关键帧的字段转换、时间求值和实际纹理绑定接入同一绘制记录。

开场两个旧格式容器的类型 4 首帧均保存第一路模式 0、编号 0，第二路模式 100、编号 0。两容器唯一的内嵌图像 `Frame.jpg` 均为 800 × 600 RGB，成员 SHA-256 相同（`61ae34b4f81013fb72105d737736d5326b5a29848df4e2690be17f8e4d7b00c5`）。窗口框容器在每个开合动作中有两个类型 4 首帧，第一路分别为编号 0 和 1，第二路均为模式 100、编号 0。以上为探针读取的原始字段。静态图像表查找、运行时替换和动态文字表面的证据见上文，仍需查明这些具体动作在当前脚本状态下的实际纹理来源，不能直接把内嵌 JPEG 当成最终画面。

开场窗口对象的脚本来源已核对到 data8 的 UTF-16LE 脚本。窗口布局在 `avg/window/layout_window.s:140–142` 加载容器并设置对象位置为 (0, 720)、层级 1500。窗口显示和隐藏例程分别在 `avg/imoscripter_custom.s:1310`、`:1332` 启用和禁用该对象，随后分别在 `:1320`、`:1341` 将同一对象登记到跳过流程。启用原版入口 `0x5aca20` 两分支均设定启用字节，仅 `0x5aca3e–0x5aca56` 另将对象字段 `+0x2e0` 交给动作选择入口 `0x5acce8`。开场原生诊断中的空动作索引应与该自动选择路径区分，不能直接当作文件动作 0 已开始播放。

原版禁用入口 `0x5ac9cc` 区分两个状态字节。若 `+0xd32` 非零、`+0xd31` 为 1 且缓存的 `*Disable` 索引有效，它调用 `0x5acce8` 后仅清除 `+0xd32`（`0x5ac9da–0x5ac9f9`）。逐帧处理入口 `0x5ab268` 检查的是 `+0xd31`，仍可进入 `0x5ab0e0`。立即清除两字节的入口另在 `0x5ab634`。因此逻辑禁用和退出绘制循环需要分别表示。退场动作完成后进入双清零入口的具体调用条件仍待核验。

长回放发现立绘 `motion_basicset.b` 的默认动作使用脚本绑定图片作为静态预览。真实容器摘要为 `5b0f2bc31cc6b14311642df53590c1efd3edec3b6a032e13b90424ce70e99b03`。默认动作的第一层四帧类型均为 0，第二层在时间 0 使用类型 4、首路编号 0、两路源矩形均全零，从时间 1000 起关键帧类型为 0。默认动作的这个已核验结构不涉及类型 16 或 17。剩余问题可集中在第 0 路运行时图像绑定、时间求值和默认动作在终点后的宿主行为。

ABMP 播放时钟的普通分支在 `0x57fd7f–0x57fdeb` 将调用者给的整数时间增量转成浮点，应用速度字段 `+0x43c`，并计入上一轮保留的不足量 `+0xfd0`，达到更新阈值后累加到 `+0xfd4`。`0x5ab3b4–0x5ab3c1` 将正数增量传入逐帧入口，`0x5ab1be–0x5ab1e2` 将同一个参数传给时钟函数。另有同步分支在 `0x5a1514–0x5a1538` 将底层浮点时间乘以 1000 后转换成整数，再经 `0x5ab14b–0x5ab1b7` 传入。已核验两条输入路径及普通分支的累加顺序。普通增量的宿主计时源和原生播放速度仍需核对。

时钟更新 `0x57f5c4` 按动作逐层处理。每层独立保存当前时间（对象 `+0x48c + 4 * 层号`），并读取该层最后一个 440 字节关键帧的起始时间字段。`0x57f623–0x57f660` 在当前时间达到或超过末帧时把该层时间固定在末帧值。不能用整个动作的最长时间替代各层各自的末帧边界。

类型 4 的绘制提交还依赖求值记录 offset `0x63`、`0x67`、`0x6b`（`0x58574d–0x585758`）。其中 `0x58c27a–0x58c2b4` 从相邻关键帧的 offset `0xc0` 取值，经 `0x58aa64` 求值后写入 `0x67`。旧格式转换 `0x592023–0x59202b` 从 offset `0x28` 读取此输入，并先经 `0x591d80` 转换。此处只核验字段传递，尚不能把该字段单独认定为绘制透明度。

类型 4 的整图顶点路径在 `0x585692–0x5856b1` 调用 `0x584a88`。后者在 `0x584af2–0x584b2f` 先用原点与传入宽高建立矩形，再在 `0x584a94–0x584aa4`、`0x584b32–0x584b52` 所示计算中，将两轴锚点分量按宽高换算并叠加附加偏移，取负后送入变换构造入口 `0x50ac98`。因此直接用宿主位置加关键帧平移作为左上角会遗漏锚点。仍需将求值记录的 `0x78/0x7c` 和 `0x98/0x9c` 四个分量回溯到文件字段和宿主配置。

附加锚点偏移的来源已经缩小到图像表。原版在 `0x5845c2–0x5845d4` 先清零输出记录 `0x98/0x9c/0xa0`，再用求值后的首路纹理编号读取图像表条目，在 `0x5845f4–0x58463f` 分别将条目 `0x38/0x3c/0x40` 写入这三个字段。该来源与关键帧的锚点比例不同，后者经 `0x58bd4a–0x58bdcd` 从关键帧 `0x70/0x74` 求值。表内三项的加载来源和开场实例的实际值仍待核验。

类型 4 在构建局部矩阵后，经 `0x5856cd–0x5856d8` 调用 `0x584a54`。该函数在 `0x584a5a–0x584a66` 将绘制上下文 `-0x90` 指向的矩阵与局部矩阵合成，并继续调用 `0x50b2cc`。随后 `0x5856de–0x5856f5` 调用 `0x581cdc` 的矩阵分支，`0x581d1f–0x581d45` 逐个变换顶点并保留变换后的 X/Y，深度写为 1000 减去变换值。状态栈另在后端提交路径修改顶点。因此宿主矩阵与状态栈是两个阶段，不能简单将宿主坐标与所有关键帧平移相加后当作最终顶点。

宿主矩阵的构造在 `0x5adf10` 内。该路径将 64 字节矩阵写入对象字段（`0x5adffb–0x5ae00c`，相对对象子结构 `+0x975`），然后经 `0x5ae0e0–0x5ae110` 依次施加缩放、旋转和平移。平移的 X、Y 来自对象 `+0x44/+0x48`，深度来自 `+0x4c` 并取负（`0x5ae06d–0x5ae087`）。`0x5ae116` 调用 `0x5adeb0`。该函数只有在对象 `+0x88` 和 `+0x32` 非零时才调用 `+0x30` 回调查找父对象。查找成功后，`0x5adeef–0x5adefc` 取双方 `+0xcad` 矩阵进行合成。`0x5ae217–0x5ae21f` 在对象初始化时清空 `+0x88`，因此需要另行确认开场对象是否写入此字段。绘制入口 `0x5ab70f–0x5ab727` 读取同一矩阵并叠加调用者矩阵。构造和读取路径已核验，开场对象的父绑定与动画时钟仍需在原生端落地。

图像对象初始化在 `0x5ae3b4` 将 `+0x84` 设为浮点 100。更新路径 `0x5ab0f9–0x5ab10f` 乘以常量 0.01 后把结果写到 ABMP `+0x43c`，即普通时钟分支所用速度倍率。原版默认倍率为 1。设速入口 `0x5ae618–0x5ae655` 将输入限制在 0 至 3000 再写入同字段。该结论解决默认速度比例，不能独立证明宿主时间增量的单位。

开场诊断中的 `dc` 字段已追到 ABMP 音频分派。原版 `0x5acf22` 写入组件 `+0x428`，`0x580274–0x5802a8` 对 `+0x478` 表做索引检查、计算通道并取出条目。`0x57e4f5–0x57e4ff` 创建这张表并写入 `+0x478`，类元数据（`0x57ac30`、`0x57ac50`、`0x57ad3b`）指向 `TABMPSound103`。`0x580340–0x58035a` 将表项资源与算出的通道一起交给回调。这条路径为 `verified` 的静态证据，原生诊断据此将字段标为 ABMP 音频通道。两个缺失图层仍需核对各自的纹理来源与替代绘制分支。

类型 4 的替代绘制门槛已定位。`0x5842e4–0x584301` 把图像表条目与像素句柄分别输出，命中 `link` 时 `0x584348–0x584366` 会同时替换这两个输出。`0x587a53` 读取第一路的条目引用（求值记录 `+0xce`）。`0x587d9c–0x587dae` 只在该条目与其 `+0x34`、`+0x4c` 均非空时设置标志。类型 4 分派据此调用 `0x5865a8` 或 `0x585660`（`0x587ea5–0x587eca`）。这是 `verified` 的静态条件。开场两条目是否满足这两个指针条件仍待核对，应沿条目构造和链接分支取证。

用锁定版本的上游适配器重新读取两个真实样本，均只含一个图像描述符，内嵌 JPEG 确认占用文件表的 slot 0。文字特效的描述符位于 offset 1814（`abimgdat14`），窗口动画位于 offset 429（`abimgdat13`），两者原始类型码均为 1，三个附加锚点字段均为 0。这里验证的是文件表，运行时替换和最终画面仍需单独取证。

`0x5ab3b4` 的直接调用点有两组来源。`0x67dfb1–0x67dfdc` 将同一调用参数依次传给三个消息图像组件，参数还可由 `0x67e6ca–0x67e6d9` 原样传入。`0x6c6c37–0x6c6c4d` 则先求值脚本参数，再将结果传给单个图像对象。后者证明该入口也接受显式脚本增量，不能用该调用点反推自动播放的计时单位。

类型 4 的普通提交只把第一路像素句柄 `+0xa4` 传给 `0x55b2e4`（`0x585792–0x5857a7`）。前置调用 `0x585671–0x585677` 将首路准备标志设为 1、第二路设为 0，因此 `0x5849f3–0x5849f7` 跳过第二路准备。首路准备函数 `0x5986dc` 检查图像条目 `+0x34`，非空时可递归调用 `0x587680` 并更新 `+0x4c` 引用的表面。这证明第二路编号不会作为第二张纹理进入类型 4 的普通提交，也定位了首路可能在提交前被更新的位置。开场图像条目的实际构造值仍待核对。

两个开场文件的图像类型码 1 在原版描述符加载器 `0x5980a5–0x5980b2` 分派到 `0x5980ec`，追加 `.jpg`（`0x5982f8`）后交给 `0x59769c`。同一加载器内写入子 ABMP 引用 `+0x34` 的 `0x597a5e`、`0x597ad0` 分支分别检查 `.b` 和 `.bt`。后续 `0x598be8–0x598c32` 先清空 `+0x4c`，且只有子 ABMP 引用存在并满足尺寸和启用条件时才重新分配表面。由此可排除原始 JPEG 描述符直接进入子 ABMP 分支。该静态结论不涵盖宿主替换过的条目，也不证明普通路径采用默认混合。

动作选择入口 `0x5acce8` 遇到编号 -1 直接返回；同编号且 `CL=0` 时也直接返回，`CL≠0` 时则继续调用 `0x57e840`。启用分支 `0x5aca4c–0x5aca56` 显式传 1。另有脚本分派分支 `0x6c7adc–0x6c7b58` 先求值两个操作数，再根据第二个求值结果是否为零构造强制标志；数字编号与名称分别经直接入口和 `0x5acd3c` 进入同一选择逻辑。命令分派在 `0x6c79a6–0x6c79b2` 将 `m` 送入该分支，求值器 `0x69bb17–0x69bb38` 将缺省空操作数写为整数 0，故省略第二参数会强制重播。`0x57e870–0x57e87a` 随后清零动画累计时钟。原生图像对象的 `m` 已按此重置已知动作的播放时钟。

图像 `skp` 在 `0x6c6ab0–0x6c6ab6` 按命令名分派，`0x6c6c37–0x6c6c4d` 将整数参数送入 `0x5ab3b4`。data8 的 `avg/imoscripter_custom.s:1215–1217` 在配置或跳过条件满足时对当前对象执行 `skp,500`。原生核心将这条指令计入已启用图像的动作采样时钟，使用对象速度，且只推进目标对象。窗口隐藏例程在第 1332 行禁用窗口动画，并在第 1341 行对同一对象调用跳过辅助例程。原生核心也允许该已核验容器的退场动作在逻辑禁用后响应 `skp`。原版入口还可触发逐帧副作用，当前接入范围限于采样时钟。

禁用的立即分支 `0x5aca04–0x5aca06` 使用虚表 slot `+0x20`。基础图像虚表从 `0x5a90ac` 起，该槽（`0x5a90cc`）指向清除两标志的 `0x5ab634`。逐帧尾部 `0x5ab228–0x5ab25b` 的 `+0x20` 调用则来自实例本身，并且只在动作编号变化、事件字段有效时执行。它不能作为退场完成时清除可绘制标志的证据。

类型 15 经绘制跳表项 `0x587e24 → 0x588037 → 0x586488` 调用 `0x55b808`，后者在 `0x55b84d` 提交命令 13，即重置绘制状态栈。该类型出现于文字特效的多个非默认动作。原生采样现在在同一动作的命令序列中应用此重置。跨对象绘制排序与最终像素输出仍待接入。

采样编号从旧关键帧 offset `0x91` 扩展到新版 offset `0x0c`（`0x591e25–0x591e2c`），再复制到求值记录 offset 6（`0x58d839–0x58d84a`）。状态压栈时，`0x55bcfe–0x55bd4e` 继承父状态，随后用非默认混合与采样编号覆盖。用锁定上游版本重新探测两份对话框底图、文字特效和窗口动画，所有已读类型 4 关键帧的混合和采样原值均为 0，后两份的类型 16 也均为 0。在这些样本中，关键帧采样覆盖无法解释开场缺层。

循环点头的两层各有一个类型 1 的时间控制记录，分别位于 6000 和 500，三项控制输入均为 0（真实 `motion_basicset.b` 的动作 4，探针 `time_control_inputs`）。该字段独立于绘制类型。`0x592059–0x592093` 将旧格式字段转换到 `0xd0–0xdc`。更新入口 `0x57f7a6–0x57f8cf` 先检查条件变量与替代索引，回退到 `+0xd4` 的索引后读取目标关键帧时间，并在目标不同于当前帧时加回超出触发时间的余量。开场原生端尚未复现此条件变量和跨帧跳转。

队列合成路径 `0x5589bd` 先复位目标的绘制状态栈，`0x558a43` 整理记录索引，随后 `0x558a75–0x558ab5` 逐条按队列顺序取记录并交给状态处理器。该处理器从同一目标的 `+0x5c` 取状态栈（`0x5585a8`、`0x5585bd`、`0x5585d4`、`0x5585f5`），不会在对象边界自动复位。这证实状态可以跨对象作用于排序后夹在压栈与出栈之间的绘制记录。实际窗口动画是否包围消息对象的提交，还需要核对三类记录的排序键。

窗口动画与文字特效的起始压栈和出栈具有不同排序输入。求值器在 `0x58b5e8–0x58b5ff`、`0x58ba3f–0x58ba52` 从关键帧 `+0xa8` 生成输出 `+0x4f`，类型 17 在 `0x5864d6–0x5864e2` 将其与宿主上下文 `+0x64` 相加。`0x559f44–0x559f4c` 将传入的值转换后写入记录 `+0x8c`，队列在 `0x558a7c` 使用该值检查处理上界。两个真实容器的首帧压栈输入均为 0，出栈输入分别为 490（窗口动画）和 10（文字特效）。这支持沿队列顺序核对它们影响的其他对象。当前原生采样只在单个动作内应用状态，跨对象顺序仍待验证。

宿主图像的绘制入口 `0x5ab644` 以对象 `+0x338` 为子结构基址。`0x5ab620–0x5ab628` 将对象 `+0x50` 转换后写入该子结构的 `+0x905`。`0x5ab767–0x5ab7a0` 在提交前读取同一字段，加上对象 `+0x90` 的继承量，送入 ABMP 绘制入口。这定位了宿主排序量的上游字段。仍需核对按钮的对应提交及队列比较器如何处理相等键，才可确定具体包围关系。

脚本 `p` 的第三个操作数在 `0x6c5990–0x6c59a5` 求值，并经 `0x6c59ee–0x6c5a06` 传给 `0x5ae718`。后者在 `0x5ae71c–0x5ae73c` 将它放入 `0x5ac7b0` 的栈槽 `+0x10`，随后 `0x5ac877–0x5ac8de` 写入目标与当前排序字段 `+0xc55/+0xc3d`。绘制入口传出的宿主排序量经 `0x5881bb`、`0x582371` 进入 `0x587680` 的上下文 `+0x64`，与关键帧排序量相加。由此可确认窗口对象本身的脚本层级 1500 会进入这条排序链，父层偏移、按钮提交和同键顺序仍应分别检查。

绘制记录比较器位于 `0x55be6c`。虚表从 `0x554624` 起，`+8` 比较槽指向此入口，`+0xc` 指向复制 180 字节记录的 `0x55be4c`。排序器在 `0x553da5–0x553db4` 和 `0x553ec5–0x553ed4` 通过该槽比较。按实际取出顺序，比较器先比较记录 `+0x8c`（升序），再比较 `+0x90`（降序），最后比较 `+0x94`（升序）。三值相等时返回 0，排序器会交换指针，因此不能假定稳定保留提交顺序。后两键分别由 `0x559f4f–0x559f5d` 和 `0x559f60–0x559f66` 写入，尚需对照具体按钮、消息和动画的记录值。

按钮类 `TButtonLib`（类名位于 `0x67c137`）继承普通图像的绘制入口。`0x67c064` 与基础图像虚表 `0x5a90c0` 均指向 `0x5ab644`。因此走此虚表槽的按钮与窗口动画使用相同的宿主主排序键计算。对严格位于窗口压栈与出栈主键之间的按钮，第二和第三键不会改变其包围关系。实际挂接前仍需验证相关按钮父层偏移以及压栈时间段。

剧情窗口隐藏按钮在 `data8.pack/avg/window/layout_window.s:35` 的 `us` 中记录类别、回调标签及调用范围。目标位于 `avg/avgsystem_custom.s:199–206`，只在系统播放模式 0 与 1 之间切换。相邻的键盘处理入口（191–198）对非零模式采用另一套切换条件，不能共用同一脚本入口。原版按钮类 `TButtonLib` 在 `0x67c626–0x67c638` 经实例的 `FOnClick` 调用宿主事件；当前原生 `us` 只将单标签标题按钮登记到 `buttonScriptTargets`。剧情按钮的多字段数据虽已保存，但事件桥尚未接入。

## 读档缩略图的双纹理提交

`verified`（第四作 data7 归档的 `script/saveload/thumimage.b`，固定上游探针与原版静态分派）。`*Enable` 动作的首帧包含类型 4（成员内偏移 88，第一路槽 2，位置 −8、−8）和类型 11（成员内偏移 763，纹理槽 0、1，位置 0、0）。读档脚本在空槽路径通过 `li,0` 绑定占位图。类型 11 的跳表项 `0x587e14` 指向 `0x587fb2`，调用 `0x585e58`。后者在 `0x585f58` 和 `0x585fab` 分别读取求值记录的 `+0xa8` 和 `+0xa4`，最终在 `0x585fc0` 调用 `0x55b214`。该路径与类型 4 的单纹理提交及类型 10 的提交入口均不同。对该类型 11 调用，`0x585fa1` 将 `0` 作为 `0x55b214` 的首个栈参数。该包装器在第二路句柄非空时，经 `0x55b226–0x55b230` 选用后端命令 4，再于 `0x55b26f` 提交给 `0x559de8`。包装器内另有命令 11 的分支，其条件是同一栈参数非零。这里的后端命令号与 ABMP 关键帧类型号属于两层分派。

命令 4 的队列表项 `0x5570fe → 0x557340` 从记录 `+0x0c` 与 `+0x10` 取两个纹理引用。在直接提交分支，`0x55738a` 调用 `0x5530b8`。后者检查两路引用及其底层句柄，准备顶点数据，在 `0x553215–0x55325d` 取两路底层句柄并连同采样及混合相关参数传给 `0x53fc40`。另一分支 `0x557394–0x5573d0` 保留两路引用并把命令号 4 交给回调。静态证据覆盖了两路输入到后端的传递。具体着色器绑定、第二路采样通道和合成公式仍待验证。

`unsupported`（当前播放器）。空读档列表的 8 个缩略图以脚本绑定的静态占位图显示。类型 11 的第二路输入如何参与最终像素，以及它和类型 4 的绘制顺序对成图的影响，仍为 `not_tested`。

`verified`（命令 4 的直接提交分支）。`0x55323a` 压入的常量 1 落在 `0x53fc40` 的栈参数 `+0x18`，因此该调用经 `0x53fc51–0x53fc65` 选中 `0x53fcab`。分支在 `0x53fcd3` 把像素回调 `0x5333a8` 传给 `0x53b4ac`。该回调使用 MMX 整数运算，先把两个输入寄存器各左移 48 位并合入常量，再执行逐 16 位乘法、右移 8 位和带饱和的加减。这里已确认直接提交使用 CPU 像素回调。采样寄存器与 PNG 通道的对应关系、最终写回和另一队列回调分支仍待核对。

`verified`（`0x53e398` 扫描路径）。`0x53b8db–0x53b8ec` 同时传递扫描入口和像素回调。扫描器在 `0x53e4fe–0x53e50f` 将采样值放入 MM1/MM3，将另一路保存的值装入 MM0/MM2，然后调用像素回调。对 `0x5333a8`，左移 48 位只保留采样值最低的 16 位，并将其送到第四个 16 位槽。因此该回调不会把第二路的四个通道分别乘到第一路的四个通道。回调之后，扫描器还会处理附加输入和目标像素。在所定位的写回路径中，`0x53e5e6` 将结果饱和打包为无符号字节，`0x53e5e9` 写入目标。原版纹理解码后的通道排列与实际读档帧选择的扫描分支仍为 `not_tested`。

`verified`（本地像素检查）。按固定探针给出的范围和 SHA-256 核对后，槽 0 解码为 160×90 RGB，槽 1、2 均为 176×106 RGBA。槽 1 的中心 160×90 区域（左上角 8、8）全部为不透明白色。外围 4256 个像素的蓝色值均与 alpha 不同，其中 3240 个为 RGBA (136, 136, 136, 0)。因此中心区域无法区分蓝色采样与 alpha 采样，外围可作为区分两者的验证输入。这里记录的是解码后的源像素，原版采样和输出仍为 `not_tested`。

`verified`（通用图像装载的静态路径）。`0x54dfd1–0x54dff4` 识别 PNG 前缀并将流位置回退四字节，随后由 `0x54e00b` 进入 `0x535a9c`。该装载器在 `0x535ab4` 调用 `0x530890` 选择解码对象，在 `0x535b34` 调用 `0x540790` 把解码对象转入运行时表面。转换中 `0x540860` 的像素拷贝在 `0x5328dc` 返回累积像素字的最高八位。整幅复制时，`0x5408e7–0x5408f3` 根据返回值是否为 255 更新表面标志。该证据可用于继续追踪透明度，但尚未定位 PNG 红蓝通道写入表面的位置，不能从此推定遮罩读取蓝色或红色。

`verified`（PNG 色型 6 的行转换）。`0x53094d–0x53096c` 对色型 6 调用 `0x530418`。该函数在 `0x530480` 和 `0x53048c` 取独立的透明度行与三字节颜色行。在 `0x530514–0x530523`，输出像素字按低位到高位依次写入颜色行的字节 0、1、2 与透明度行的当前字节。透明度放在最高八位，RGB 三个颜色字节保持解码器行缓冲的排列。下一处需要核对的是解码器向颜色行写入红蓝分量的顺序。

`verified`（PNG 色型 6、8 位非交错行）。`0x52aac4` 的色型 6 表项指向 `0x52ab8f`，位深 8 在 `0x52aba5` 选用回调 `0x52a90c`。回调把 PNG RGBA 行的第 3 字节原样写入独立透明度行（`0x52a921–0x52a92a`），将第 2、1、0 字节经同一查表依次写入颜色行（`0x52a92e–0x52a962`）。结合 `0x530514–0x530523` 的重新打包，此路径的运行时像素内存顺序为 B、G、R、A。若该表面未经再转换进入已定位的最低字节采样路径，采样值对应查表后的蓝色。实际读档纹理的表面传递、扫描分支选择和查表结果仍待验证。

`verified`（真实缩略图成员头）。三个 PNG 的成员 SHA-256 与逐块 CRC 均已核对。槽 1 遮罩与槽 2 特效图的 IHDR 均声明位深 8、色型 6、非交错，两者都只含 IHDR、IDAT、IEND。槽 0 占位图为位深 8、色型 2、非交错。由此可将槽 1、2 的像素排列与上述 BGRA 行转换对应。原版的解码表初始化例程 `0x52e248–0x52e25e` 把 `+0x13d` 的 256 项设为恒等映射。素材内没有可覆盖默认颜色参数的 PNG 附加块。解码器是否依据宿主参数重新计算这张表，仍需核对其另一写入点 `0x52c3ec`。

`verified`（颜色表的文件内触发条件）。原版 PE 文件偏移 `0x126058`、`0x126089` 的指针都指向 `0x52c364`，位于 `TChunkgAMA` 的类型记录附近。该处理入口在基础块解析成功且 `0x52c2b4` 返回非零时才进入重算循环（`0x52c383–0x52c398`），并于 `0x52c3ec` 写颜色表。缩略图的两个 RGBA 成员没有 `gAMA` 块，因此素材本身不触发这个重算入口。仍需核对宿主是否有独立颜色转换，以及遮罩从解码表面到采样入口的传递。

`verified`（另一条 CPU 扫描路径的直接读入）。`0x53b7f2` 将 `0x53bf50` 选作扫描入口。其单像素分支在 `0x53bfcc–0x53bfe1` 与 `0x53bff6–0x53c00c` 分别以基址、行步长和四字节像素步长寻址，直接读取两个像素字。随后 `0x53bff0`、`0x53c01b` 依内存顺序将字节扩展为 16 位槽，在 `0x53c024` 调用像素回调。这条扫描路径在读取与回调之间没有通道重排。该分支是否被真实读档帧选中，以及输入表面在到达扫描器前是否已经转换，仍为 `not_tested`。

在原版 PE 的直接提交分支中，`0x53fcae–0x53fcb1` 先对参数 `+0x2c` 调用 `0x533394`。该助手将参数左移 23 位，保留最高字节，并把其余三个字节设为 `0x80`。随后才把调整后的参数传入 `0x53b4ac`。像素回调 `0x5333a8–0x5333eb` 对每个 16 位槽先执行低位乘法和无符号右移 8 位，再与第一路相减，乘以回调参数的对应字节，有符号右移 7 位并饱和加回第一路。扫描路径 `0x53c069–0x53c0a3` 在回调之后还可能执行颜色乘法、饱和加法及目标像素混合。因此该回调的结果只能视为合成中间值，读档帧实际传入的参数、扫描分支和最终输出仍为 `not_tested`。

真实 `thumimage.b` 动作 0 的类型 11 首帧在现有摘要校验配方中记录 `sampling=0`、`blend=0`、字面透明度 255、纹理槽 0 和 1。静态分派中，`0x57e328` 将采样字段 0 映射为 0，`0x553242` 调用的 `0x54fe9c` 也将输入 0 映射为 0。若该值沿直接提交分支到达 `0x53b4ac` 的 `+0x14` 参数，则 `0x53b77c–0x53b794` 得到第二个选择量 0。第一个选择量另行计算。两者皆为 0 时，`0x53b80e–0x53b81e` 选择扫描器 `0x53ed38`，该扫描器与 `0x53bf50` 使用同样的回调权重及固定掩码布局（`0x53ed62–0x53ed93`）。因此仅凭素材的采样字段还不能选择最近邻扫描实现，实际队列状态及第一个选择量仍须核对。

第一个扫描选择量已追到顶点数据。原版 `0x53b6c0` 初始化为 2。顶点数为 4，且 `0x535518` 对三组坐标的四角比较均通过时，`0x53b723` 改为 1。`0x535518` 比较两对横坐标和两对纵坐标，验证四角是否轴对齐。之后两次 `0x53534c` 检查均通过时，`0x53b77a` 改为 0。该助手读取相对四角的坐标差，对差值下界及两条相对边长度之差进行浮点比较。采样选择量为 0 时，选择量 0、1、2 分别对应 `0x53ed38`、`0x53c89c`、`0x53bf50`。真实缩略图最终提交的三组顶点坐标仍待重建。

数值求值器的模式 0 已核对。跳表 `0x589cbc` 将模式 0 分派到 `0x589d17`，后者调用 `0x589688`。该助手先将有符号整数转为浮点，输入低于 `0x10000000` 时直接返回，因此传入的字面零在这一阶段仍为零。类型 11 顶点打包的 `0x581d47–0x581d5b` 则逐字复制两路纹理坐标。若零值确实在原版中被展开，展开点需要在关键帧表进入求值器之前或其他已选定的分支中继续核对，不能归因于上述模式 0 转换或顶点打包。

零矩形的展开点已确认。绘制准备在 `0x58455e–0x58458b` 分别将两组源矩形的字段地址连同 `+0xa4/+0xa8` 的图像句柄传给 `0x584164`。该助手比较全部四项是否为零，并检查句柄非空。命中后调用 `0x54df94` 和 `0x54cc80`，分别写回该路图像的宽和高。第二路因此使用自身句柄的尺寸。此处覆盖绘制准备的静态路径，仍需确认读档帧两路实际句柄、坐标和最终输出。

几何选择量 1、采样选择量 0 的扫描器 `0x53c89c` 也使用已实现的回调参数布局（`0x53c8c6–0x53c8f7`）。它在扫描行开始时将两路纵坐标各自算术右移 16 位并计算行基址（`0x53c900–0x53c917`）。在单像素分支，每路横坐标各自算术右移 16 位，直接读取对应像素字并按各自步长推进（`0x53c932–0x53c95c`），然后扩展字节并调用像素回调。这里确认的是整数采样和回调输入，横纵步长初值、目标混合和可选第三路输入仍须核对。
