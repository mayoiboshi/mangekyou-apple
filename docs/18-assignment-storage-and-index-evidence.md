# 18 — 赋值、变量存取与下标证据

2026-11-07，P1 第七轮。目标是补足未来解释器所需的存取契约，仍不执行脚本，不实现存储后端、游戏引擎、播放器或界面。

## 本轮实际完成

对同一摘要固定的主程序候选，通过 REA/Ghidra 取得 31 项静态观察，又以独立命令重新取得全部观察，错误 0、清理完成，31 个 evidence ID 全部一致。通过现有 LLVM 只读工具补查 7 个小范围尾部窗口，没有修改原始指令或 Ghidra 的函数元数据。

`native-variable-report.json` 包含 14 项有范围和摘要的机器指令事实，以及单独标记的 5 项 `inferred` 契约。目标、查询选择器和工具版本分别追溯到 `native-variable-plan.json`、`native-variable-windows.json` 和 `toolchain-lock.json`。完整反编译、汇编和运行工具的日志只在 `private/p1-round7/`。

`tools/value_use_analysis.py` 重新读取合法研究副本、核对语料摘要并重新词法分析；复用现有候选表达式解析器建立赋值/更新与标识符的语法角色关系。它不依赖先前生成的 AST 内容，不读写变量。完整标识符仅保存到私有目录；公开示例只含摘要、语法形状、原始字节引用和候选角色。

## 对未来执行器最有影响的发现

### 赋值成功路径产生数值 1

表达式核心的 `0x69c2ef–0x69c33d` 路径先解析一个操作数，再把另一个原始描述符传入赋值帮助函数 `0x69b260`。成功后明确构造 tag 0、偏移 4 数值为 1 的描述符并压回栈，而不是直接传播右值；机器事实为 `assignment_success_pushes_numeric_one`。

结合第五轮 `*h` 的 `=` 映射，将该路径解释为“赋值成功表达式得到数值 1”仍标记 **Hypothesis / inferred**。原程序没有执行过。不能照搬其他语言的赋值返回规则，更不能因为当前语料没有嵌套赋值就略去这个行为。

赋值目标检查要求非空原始字段、tag 3，并排除双引号。数字首字符另经 `0x415b0c` 检查返回寄存器对；这个帮助函数不同于上一轮的 32 位整数解析函数。尚未恢复它的完整数值范围，未将上一轮模型套用到目标合法性检查。

### 名称查询具有三层顺序

`0x69f3b0` 的调用/比较指令依次查询上下文，随后查询类别 2、类别 1；每层用 `-1` 表示未找到，命中分别输出 3、2、1。`lookup_order_category_3_2_1` 给出原始范围。

第二轮 `native-report.json` 的 `variable_category_selectors` 另记录声明分派：`var`、`gvar`、`svar` 分别选择 3、2、1。两组证据可形成 `var → gvar → svar` 的候选名称遮蔽顺序；仍不能据此确定生命周期、跨调用继承或存档持久化。类别 1/2 的取存储函数还会优先选择对象中的替代指针，再退回另一字段；不能简单等价为三个固定全局字典。

上下文选择函数 `0x6a0264` 对索引做非负和数量边界检查，但创建、压栈、弹栈及返回恢复的完整路径未闭合。名称查找还包含缓存和可选规范化；UTF-16 分支中的 ASCII 大写转换不证明通用 Unicode casefold 行为。

### 读写权限、目标类型与对象实现均需保留

读取路径在未旁路时检查对象 `+0x2c` 的位 1，写入检查位 2。写入前复制值描述符，并用目标对象的声明 tag 替换描述符 tag。结合第六轮观察到的双字段缓存，未来执行器需明确各字段与目标类型的关系；目前没有实现隐式类型转换。

实际元素读取/写入最终分别走对象虚表 `+8` / `+0xc`，因此这里只获得了公共访问入口，尚未恢复整数、字符串、列表、表和引擎对象的全部虚方法、引用所有权与销毁方式。

### 下标先经列表与步长处理

`0x69f900` 的一条路径按逗号建立列表，限制最多处理 4 项，以 `count-1-i` 取项，逐项调用表达式核心并填入连续字段。该事实不证明源码的求值方向：列表构造顺序及字段到源码坐标的映射仍需核对，也不把嵌套 `a[i][j]` 语法计数当作运行时数组 rank。

`0x69dd30` 以 32 位乘加组合基值及三个存储步长。读取和写入的共同边界要求线性结果非负且小于总元素数，再调用虚方法。此局部检查不证明每个坐标分别受界，也不证明所有下标输入都经过相同路径。维度构造、步长顺序、溢出和不合法索引的错误传播仍未确认。

## 反编译器缺口与 Unknown

基线 Ghidra 在清理 RET 处截断了若干函数。独立窗口显示：

| 续接位置 | 静态观察 |
|---|---|
| `0x69f5dd` | 从栈中一个字节扩展载入 EAX，随后返回 |
| `0x69f83a` | 从另一栈字节扩展载入 EAX，随后返回 |
| `0x69d579` | 从栈中状态字节扩展载入 EAX，随后返回 |
| `0x69e553` | 从栈中一个 32 位字段载入 EAX，随后返回 |

字节及独立解码可验证；将这些续接接入完整正常流、命名具体状态含义仍为 `inferred`。没有把反编译器的 `void` 表示用作真实调用约定，也没有为制造成功而修改函数或代码。

7 个窗口中还有 3 个 `<unknown>` 解码位置：`0x69fb2c`、`0x69fb2e`、`0x69f84d`，均位于上述小尾部 RET 之后的探查范围。它们可能属于后续数据或其他未识别内容，未认定为可执行指令。报告逐项保留位置，`linear_window_coverage_status=unsupported`；14 项指定指令事实成立不等于整个窗口都解码成功。

## 语料关系与未支持项

对全部 379 份保留版本中的 `cal/if/for/case` 字段重新分析，得到：

| 候选结构 | 数量 |
|---|---:|
| 字段 / 可建立 AST / 未支持 | 8,130 / 8,128 / 2 |
| 赋值位置 | 5,088 |
| 标识符目标 / 带下标目标 | 4,407 / 681 |
| 后缀更新位置 | 407 |
| 其中嵌套在其他结构里的更新 | 6 |
| 赋值目标标识符候选角色 | 5,088 |
| 值位置标识符候选角色 | 7,509 |
| 更新目标标识符候选角色 | 407 |
| 下标参数标识符候选角色 | 466 |

赋值中 `cal` 占 4,713，`for` 占 375；更新中 `cal` 占 38，`for` 占 369。它们是保留各包版本的出现次数，不能当作独立运行路径数量。

所有关系只表示语法角色，置信度为 `inferred`；真实读写方向、副作用时点、绑定的声明、求值顺序及存储对象均没有因此升级为 verified。6 处嵌套更新说明副作用时点值得优先确认，不能只实现循环末尾自增来冒充全部更新行为。

两处空 `cal` 字段继续明确未支持。8 条没有操作数字段的零参数 `for` 保留 `not_tested`，没有补默认条件。其他 34,131 条命令记录按范围排除并逐 token 计数，非命令记录也有类别计数；未知和排除没有静默消失。

## 独立复现与检查

需要已有合法导入的 P0/P1 研究副本、固定摘要的主程序候选和已记录版本的本机分析工具。`GAME_DIR`、`GAME_EXE_REL` 等由使用者提供，代码不硬编码游戏绝对路径。

```sh
.venv/bin/python tools/rea_static.py \
  --game-dir "$GAME_DIR" --exe "$GAME_EXE_REL" \
  --plan docs/native-variable-plan.json \
  --output private/p1-round7/native-reproduced \
  --rea-command "$REA_COMMAND" \
  --java-home "$JAVA_HOME" --ghidra-dir "$GHIDRA_INSTALL_DIR"
.venv/bin/python tools/native_windows.py \
  --game-dir "$GAME_DIR" --exe "$GAME_EXE_REL" \
  --plan docs/native-variable-windows.json \
  --output private/p1-round7/windows
.venv/bin/python tools/variable_analysis.py \
  --game-dir "$GAME_DIR" --exe "$GAME_EXE_REL"
.venv/bin/python tools/value_use_analysis.py --assets-dir private/real-assets
.venv/bin/python tools/research_checks.py --stage round7 \
  --game-dir "$GAME_DIR" \
  --artifact reports/p1/native-variable-report.json \
  --artifact reports/p1/value-use-report.json
```

完整原生观察、标识符名称和逐项关系在 `private/`；公开报告只含脱敏元数据。新工具仍限制文件数、输入总量、字段和节点数、逐文件报告体积，并拒绝输出与输入重叠及符号链接路径。

本轮新增 12 项合成测试，见 `tests/test_value_uses.py`：赋值与值角色分离、下标依赖、后缀更新、嵌套结构、未证实的目标拒绝、嵌套下标不冒充 rank、字符串隔离、原始 UTF-16 字节位置、公开脱敏及未知解码的完整记录。检查结果见 `round7-tests.json`、`round7-readiness.json`；其中保留窗口未支持和字段失败限定，不把检查通过当作游戏兼容。

实际研究环境 143 项通过；系统 Python 140 项通过、3 项可选检查跳过；上游 26 项通过、8 项商业夹具检查跳过。20 个已有摘要的原始关键文件及本轮开始前的全部冻结 P0 报告均保持一致。完整伪代码和逐项标识符关系仍被 Git 忽略，未提交商业资源。

下一步最有价值的范围是后缀更新的副作用时点、调用/返回上下文创建及回收，然后再连接分支状态与变量生命周期。对象所有权、存档和演出时序仍是完整原生移植的关键缺口；本轮不宣布 P1 全部完成或允许运行时开发。
