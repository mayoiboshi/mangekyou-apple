# 08 — 跨包差异与覆盖顺序

比较对象是 P0 解码成功的全部 `.s` 和 `.txt`；归档总目录另外用于列出同名路径。路径对照使用 NFC 和 casefold，**只是匹配假设，不证明 QLIE 的实际路径规范化规则**。

游戏索引中有 260 种重复逻辑路径，含资源、文本及嵌入 key 文件名；其中本轮有解码副本的文本重复组为 177 组，每组实际有两个版本。

| 比较结果 | 组数 | 可确认的结论 |
|---|---:|---|
| 原始解码字节一致 | 53 | 两份研究副本内容相同 |
| 解码并统一 CRLF/CR/LF 后相同 | 113 | 规范化文本相同；不能据此证明引擎对编码/换行的行为一致 |
| 规范化文本不同 | 11 | 有实际内容差异，必须保留两个版本 |

另保存不含正文的行区间差分、token 序列摘要和词法字段摘要。比较基准只用于列差异，不代表选中的运行时版本；工具也处理三版本样本，避免只检查前两份。

11 组实际不同的路径：

- `avg/avgsystem_custom.s`
- `avg/imoscripter_chara8e.s`
- `avg/imoscripter_image.s`
- `avg/imoscripter_reptextlist.txt`
- `avg/imoscripter_sound.s`
- `scenario/本編/t16_03.s`
- `scenario/本編/t19a_03.s`
- `scenario/本編/t19b_03.s`
- `scenario/本編/t20a_01.s`
- `script/albummode/viewfunction.s`
- `system/etc/game.txt`

其中 8 组连候选 token 序列也不同，2 组 token 序列相同但字段不同，1 组只在当前词法结构投影之外存在文本差异。最后一种仍不能称为“不影响行为”：替换文本列表等载体的内容本身可能参与程序行为（Hypothesis），当前投影也不是完整语法。

P0 对 `.s` 得到的 137 个重复路径与本轮 177 个文本组不矛盾：本轮增加了 `.txt`。有些包相同文本使用不同编码，直接以原始摘要判定“脚本逻辑已修改”会扩大改动范围。

**覆盖顺序仍为 not_tested。** 包编号、文件名含“补丁”、编码较新，都不足以证明载入优先级。工具不会把 data8 自动放到 data7 之上；也没有修改、重打包或合并原归档。下一轮应优先为这 11 组建立证据，而不是先把全部副本压成一个运行目录。
