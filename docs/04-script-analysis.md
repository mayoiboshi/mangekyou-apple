# 04 — QLIE 剧本静态分析

实际找到并解码 283 份 `.s`，不是从 EXE 猜测载体。其中 199 份有 UTF-16LE BOM；84 份无 BOM 且通过严格 CP932 解码。后者的编码仍标为 `inferred`：能解码不等于每个字符映射都与原引擎一致。未发现需要解释为独立二进制操作码流的证据，脚本版本号没有臆造。

物理结构共 **653,633 行**，合并连续空行为可回溯 span 后是 **152,675 条 IR 记录**。空行填充很多，不能丢弃后重新编号。未遇到解码或词法错误。`.s` 跨包重复逻辑路径有 137 种，保留每个版本；没有擅自选择生效版本。

## 四级能力

| 等级 | 当前结论 | 依据及限制 |
|---|---|---|
| 正确提取台词 | verified：提取规则的一致性；实际台词完整性 inferred | 283 份显式 Qlie 导出与独立投影的 28,598 条消息完全一致；167 份无消息。text 中仍可能有宏/布局文字，不能把数目当唯一台词数 |
| 恢复文本顺序 | verified：物理文件顺序 | 记录原始字节 offset/length 和行号；不是运行时路径顺序 |
| 识别控制结构 | inferred：词法结构 | 观察到 if/else、jmp/sub/ret、var/gvar/cal、for 等标记；没有据名字赋予正式语义 |
| 理解完整执行语义 | unsupported | 宏展开、表达式、变量域、调用约定、条件结果、时间线和存档模型均未建立 |

记录中包括 1,868 个标签候选、442 个 include 候选、31,901 个反斜杠命令、21,915 个行标记、15,190 个音频标记候选；共 169 种词法 token。声音标记不自动等于“语音”，图片路径不自动等于“背景”。

## 源码对照及工具不足

固定 [msg-tool script.rs](https://github.com/lifegpc/msg-tool/blob/0356bb93be7c1f5b11ec22864919200cf7455e33/src/scripts/qlie/script.rs) 的 `parse:296–325` 按 `@@@`、`@@`、`^`、反斜杠、`【…】`、全角 `％` 分类。`extract_messages:429–477` 把姓名关联至下一文本，将 `[n]` 替换为换行，另处理 select/savetext。它不执行表达式、不决定跳转、不恢复完整演出。

自动格式识别在 76 行以 `&&` 要求同一行等于两个不同头文件名，成功条件不可达（verified，源码逻辑）。真实试验也观察到自动模式退出码 0 而不产生输出。因此交叉验证必须显式指定 Qlie 类型，不能因自动识别失败就认定真实脚本不可解析。该模块的 `test_tag` 只验证参数解析/重建，不覆盖第四作脚本语义。

第一作 `mangekyou_util/splt.py` 用前缀排除命令并查找非 ASCII 文本，属于汉化提取启发式；包含其他保存标签约定，不能用它给第四作未知字段定意。Python2 环境及依赖问题也阻止直接作为本机验证基线。

本地不在缺证据时修改上游检测条件来制造通过结果。msg-tool 的原生构建、显式导出与内容一致性结果由 `reports/p0/script-report.json` 的 `extractor_crosscheck` 单独记录；只有命令实际完成才标为 verified。真实导出正文只留在 `private/`，不进入报告或 Git。

本机原样构建使用 `--locked --no-default-features --features qlie`，ARM64 release 成功。`test_tag` 在 lib/bin 两个测试目标中各执行一次，是同一个源码用例，不能计为两项独立覆盖。283 份脚本中 116 份产生消息 JSON、167 份按工具约定不输出空消息文件；全部与独立投影一致，无差异或失败。这验证消息抽取规则和顺序，不证明筛选出的消息都是真实对话、所有人名绑定正确，或脚本可执行。

## 带字节来源的 IR

每条记录保留 `source_file`、`byte_offset`、`byte_length`、`record_type`、`raw_bytes_reference`（源文件 SHA-256、offset、length、记录 SHA-256）、`decoded_text`、`operands`、`confidence`、`unknown_reason`。真实报告的正文和参数值默认留空，保留摘要。空白 span 额外记录 `line_count`，原始范围依然完整。

不对解码结果重新编码来计算 offset，避免 CP932 别名字符和 UTF-16 单元导致偏移漂移。BOM 在字节位置中计入。未知命令保留原 token 和字段摘要；未知语义明确标记 inferred，不给它执行实现。`reports/p0/script-report.json` 有 24 个不含台词的真实结构记录示例，完整本地 IR 在忽略目录。

## 静态资源引用

实际生成 **2,639 条带源文件、字节位置和记录摘要的候选边**。其中 434 条为单一字面路径匹配，501 条存在跨包/解析基准歧义，另 1,704 条尚无确定映射（其中可能有大小写候选）。这些是资源目录中的静态字符串对应，不是经过验证的运行时绑定。

合法脚本常有 `../` 引用。它与归档成员的路径穿越风险不同：本工具只做字符串归一化、保留候选，绝不按该路径访问文件。以脚本相对位置或资源挂载根查找均可能成立，未确认时保留歧义。扩展名缺省、变量拼接和宏参数产生的标识符尚未映射。

背景、立绘、语音、BGM、音效、动画六种角色均保留 `Unknown/not_tested`；不凭 `bg02`、`music01` 的名字确认命令语义。完整图及所有证据位置在 `reports/p0/reference-graph.json`。源文件可解析和路径字符串能匹配，仍不足以制作“顺序播放台词”的移植替代品。
