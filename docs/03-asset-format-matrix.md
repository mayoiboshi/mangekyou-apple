# 03 — 实际资源格式矩阵

本次从 9 个游戏包解码 **410 项、20,280,560 字节**；包含全部 283 份 `.s`、96 份 `.txt`，以及 31 项代表性图片/媒体/复合资源。每项均由上游进行存储 hash、解混淆、解压（如有）及解码长度检查。卸载包未采样。选择策略是每种候选扩展名取首项和最小的有界项，明显偏向小文件；不是全资源覆盖测试。

| 实际签名 / 解码结果 | 样本数 | verified 的范围 | 仍未确认 |
|---|---:|---|---|
| DPNG | 6 | 20 字节头、拼片描述、边界；上游转换成功，输出 RGBA/尺寸/摘要记录 | 与原引擎重叠半透明拼片合成是否一致、所有图片 |
| 标准 PNG | 4 | Pillow 实际解码，宽高、通道、alpha extrema | 原引擎色彩管理及演出用途 |
| abmp12 + NUL 填充的 16 字节头 | 9 | ABMP12 容器版本签名 | 内部区段、时间线、递归资源、IMOAVI/模型等 |
| Ogg | 10 | ffprobe 确认 Vorbis 音频、Theora 视频或复合流 | 所有媒体、循环点、同步、渲染/播放 |
| RIFF/WAVE | 2 | ffprobe 确认 pcm_s16le、44.1 kHz、双声道 | 原引擎混音/延迟 |
| 文本 `.txt` | 96 | BOM/严格解码、行数、摘要；无二进制控制字节 | 配置/宏/剧本载体的完整用途 |
| `.s` 文本 | 283 | 单独进入脚本分析 | 完整执行语义 |

PNG/DPNG 的具体尺寸和透明度见 `reports/p0/asset-report.json`，不展示或提交 CG。合成 DPNG 验证了非重叠拼片的逐像素结果和 0/128/255 alpha；另有重叠拼片测试，确认 Python 实现采用后片像素替换。旧 C 使用 GDI+ DrawImage，存在混合行为差异的可能性（**Hypothesis**），未比较原引擎输出，不能宣称转换器在所有演出场景正确。

实际媒体中观察到 Vorbis 44.1/48 kHz、单/双声道；Theora 样本为 1280×720，也有同时包含 Vorbis 与 Theora 的 Ogg。检测依据是容器/流信息，不是 `.ogg` 或 `.ogv` 后缀。ffprobe 只读取本地副本并限制协议及时间，不调用播放器。

没有证据表明本次包索引存在独立字体文件；**Hypothesis**：可能使用系统字体，或把相关内容嵌在其他载体内，均不能确认。没有据候选清单虚构 MP3、FLAC、MP4、JPEG、IMOAVI 在游戏归档中的存在。安装目录网页 JPEG/PNG 与安装器 BMP/ICO 不等于游戏演出资源。

ABMP12 已识别但未展开，是明确的未支持项。上游 `abmp.py` 声明支持 10/11/12 和部分嵌套类型，其源码能力及合成测试不能替代本作真实容器内部验证。后续须先为内部压缩大小、嵌套总量与命令语义建立边界，再扩大样本。
