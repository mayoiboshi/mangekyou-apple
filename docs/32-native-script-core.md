# 32 — 原生脚本核心与真实启动片段

本轮将应用推进到显式实验性脚本执行，不再只有资源检查。范围授权沿用用户“可以做完整应用”；原游戏只读、禁止运行商业 EXE/DLL、不得上传商业内容等约束保持不变。**完整原生游戏仍未实现。**

## 已完成的执行路径

`MangekyouCore` 新增源字节映射、QLIE 候选记录/字段解析、受限标量表达式、变量存储、条件分支、同文件调用/跳转与零参数返回。不是另造一门演示脚本语言；输入直接是现有 `.s` 副本的原始字节。但所有执行都属于显式 `experimental_static_contracts_v1`，模型为 `inferred`，原引擎等价为 `not_tested`。

开发版 0.2.0 已接入同一核心：选择 `.s` 后只读取元数据，按下“实验性执行检查”才执行候选子集。不会显示/顺播未知正文，不保存游戏状态，不将未知指令当空操作。

本轮实际在 GUI 中选择已有 `data0.pack` 研究副本目录中的 `startup.s`：看到 87 条记录、23 条候选命令，点击检查后显示处理 20 条记录、调用深度 2、条件跳过 5 条记录，并停在第 45 行、字节 1,012 的双参数 `sub`。这个停止位置与命令行相同。只观察了元数据和诊断，没有向外部传输商业正文、图像或声音。

UI 导入后的两次读取超时保留为失败观察。进程采样显示主线程处于正常事件等待；画面已显示导入完成。重新取得窗口绑定后可继续读取和操作，未修改应用来“修复”一个未证实的死锁。确切超时原因仍未验证，不能把采样或重取成功写成根因证明。

## 与实际语料交叉验证

`tools/verify_native_scripts.py` 构建 ARM64 原生命令行程序，核对来源摘要后读取全部 379 份保留版本。用独立 Python 模型重新计算三组摘要：

1. 完整解码文本的 UTF-8 摘要；正文不导出。
2. 每个 Unicode scalar 的值、原始字节起点和长度的流式摘要。
3. 记录种类/顺序/范围、命令字段文本/命名字段/解引号值与字段原始范围的摘要。

三组均无差异，共 291,273 条词法记录。包含 `.s` 和系统 `.txt`，没有删除不同包版本。这里验证的是**两个项目解析器在既有样本上的一致性**；两者可能共享尚不完整的语法假设，不是独立原引擎 oracle。宏、前缀和行预处理的完整执行仍未支持。

CP932 按原字节建立跨度，不能重编码后反推位置；Windows 932 使用本机 SDK 声明的 `kCFStringEncodingDOSJapanese=0x0420`。Apple 转换器不接受的五个单字节扩展由明确的字节映射补齐，并以 Python CP932 和自建别名字节测试核对。UTF-16 代理对按四字节定位；不做 Unicode 规范化或一般 Unicode casefold。源码、范围和全文摘要分别保留，别名字节不因解码文本相同而丢失身份。

## 真实启动文件中的实验结果

选中来源 `data0.pack/startup.s`，身份由 P0/P1 既有摘要绑定。当前运行从**该副本的文件开始位置、全新模型状态**出发，不代表 Windows 引擎真实选择了它作为入口，也没有加载原存档/系统状态。

| 命令字节位置 | 本机候选操作 | 证据限制 |
|---:|---|---|
| 48 | `svar` 声明模型中的整数 | 名称前导 `#` 保留为身份的一部分；零初始化为假设 |
| 92 | 执行整数赋值/计算 | 受限新运行时结果，不是原版算术对照 |
| 150 | 按精确的 1 判断；本次走非真分支 | 当前全新状态下的候选路径，不推定已有存档时相同 |
| 284 | 进入同文件唯一字面标签 | 创建新的候选局部帧，实际原版调用 ABI 未验证 |
| 1,012 | 遇双参数 `sub`，停下 | 第二字段/跨文件或上下文绑定尚未实现；没有直接把它当作普通参数 |

初次运行曾停在声明名称的 `#` 前导字符；检查实际字段形状及既有标识符模型后，增加“保留 # 的标量名称”并用自建用例区分 `#counter` 与 `counter`。初次停止报告仍在私有目录，没有删除失败来制造兼容性。第一次编译的初始化捕获错误也保留日志；修正本机 Swift 初始化顺序后编译通过，未改任何上游源码。

机器产物 `reports/p1/native-script-report.json` 保留实际停止的 `unsupported` 状态、20 条轨迹和 24 项源字节引用（包含目标及跳过范围）。每项重新核对相对源文件、全文摘要、offset/length、区间摘要和可核对的行号。公开报告没有参数、变量名、字符串值或台词；原生记录类型故意不实现自动 Codable，仅允许元数据摘要序列化。Python 发布边界拒绝意外新增正文/变量字段。

**字节位置属于解码后的合法研究副本，不是压缩 PACK 中的偏移。** 归档来源通过冻结 P0 和 P1 corpus 的 origin 追溯。

## 当前模型的边界

逐项依据与未支持行为见 `docs/runtime-profile-v1.json`。特别需要保留：

- 只实现二字段 `var/gvar/svar,int,name` 标量模型；初始化、完整局部生命周期、权限、替代存储对象、别名和序列化没有原版证明。查找次序有静态证据，不能由此推出三个字典就是完整原版对象实现。
- 数字/处理组来自既有取证；算术限于不溢出的整数。赋值只允许最外层一次，返回数值一作为已有候选契约。拒绝嵌套赋值、更新、下标、对象、浮点、字符串运算/隐式转换和移位；条件赋值也明确拒绝。
- 逻辑两侧都先求值，且只有整数一为真。条件块限于已实现的 `if + then + 可选 else + end` 形状。跳过的记录通过完整区间、数量和类型记账，不能当作已执行或未知指令已支持。
- 同文件 `sub/jmp` 只接受一个唯一字面目标。只实现无参数 `ret` 返回调用者；`subp/subr`、命名/根返回、跨文件、额外字段和跨控制域跳转均停下。
- BOM、纯布局、空行和标签在本模型中推进；普通正文、注释候选、include、行标签、宏/配置和声音标识符均停止。不能因词法分析说“注释候选”就自动忽略它。
- 单指令失败采用新运行时的原子提交并停止策略，**原版错误回滚未知**；不会把这个更易检查的策略写成原引擎行为。当前没有接入对象回调、声音、动画、完整存档或时间线。

限制：源文件 16 MiB、400 万 scalar、10 万行、20 万记录、4,096 字段/命令、分组/AST 深度 64、1,024 表达式 token、4,096 标量和 64 调用帧。单次默认 10,000 步，运行有单调时钟/取消检查。单行大量片段在建立全部记录前拒绝。批量输入最多 2,000 文件、128 MiB、120 秒；失败和未覆盖范围不得静默消失。

## 测试与复现

本轮新增 25 项 Swift 脚本测试，连同已有资源测试共 38 项通过；另有五项 Python 发布边界测试。覆盖别名字节、代理对、字段范围、引号/分组、预算、非宿主语言优先组、精确一/急切逻辑、赋值结果、作用域、嵌套跳过、调用返回、未知停止、错误原子性以及脱敏。它们验证自建运行时，不是商业游戏回归。

最终整体检查 `round21-readiness.json` 为研究检查通过：研究 Python 296 项通过；系统 Python 293 项通过、3 项跳过；上游 26 项通过、8 项缺失商业夹具跳过。跳过不算通过。20 个已有关键原文件摘要保持一致，冻结 P0 与本轮快照一致；完整原生游戏仍为 `not_tested`。本轮没有提交商业资源或导出的完整内容，应用和构建缓存也保持在 Git 忽略范围。

```sh
swift test --package-path native
python3 tools/build_native.py
open build/Mangekyou.app
.venv/bin/python tools/verify_native_scripts.py --assets-dir "$ASSETS_DIR" \
  --script-file data0.pack/startup.s
python3 tools/verify_native.py --game-dir "$GAME_DIR" --assets-dir "$ASSETS_DIR" \
  --output reports/p1/native-app-round21.json
.venv/bin/python tools/research_checks.py --game-dir "$GAME_DIR" --stage round21 \
  --artifact reports/p1/native-script-report.json --artifact reports/p1/native-app-round21.json
```

这里 `$ASSETS_DIR` 指既有 `private/real-assets`，使用者可另行提供同摘要副本。原生命令行也可只读取一个文件；`--experimental-run` 是显式启用执行，缺省只做元数据分析。遇未支持返回退出码 2，不能将它重标成通过：

```sh
swift run --package-path native mangekyou-script --assets-dir "$ASSETS_DIR" \
  --script data0.pack/startup.s --experimental-run
```

整作移植下一步是补足二字段调用与文件/上下文的绑定证据和实现，再接入有明确许可的归档资源访问、对象指令和音画。当前的资源包包尾识别不能代替索引/负载读取；现有无许可证研究解析器没有被复制或打包到应用。
