# 36 — GPL 归档读取候选的 ARM64 交叉验证

本轮仅做资源后端的本机研究验证，未扩展引擎、播放器或界面。原生应用仍没有 PACK 索引/负载后端，真实启动片段此前的 `table` 停止点未改变。不能把本轮读取成功称为整作兼容。

## 为什么验证另一条读取路径

既有 Python 解析器已用于 P0，但固定版本没有明确许可证，不能直接进入待分发运行时。固定 msg-tool 的归档模块声明 GPL-3.0-or-later，提供库接口，值得在相同输入上独立验证。此次是不同工具路径的结果交叉检查；没有证明这些工具的历史算法来源彼此独立。

固定版本和文件摘要仍以 `docs/upstream-lock.json` 为准：`lifegpc/msg-tool@0356bb93be7c1f5b11ec22864919200cf7455e33`。编译前后均核对该记录的 235 个文件；没有修改上游文件，也未将上游源码复制进本项目。

## 源码中实际确认的接口和风险

- `Cargo.toml:117–119`：`qlie-arc` 在脚本功能外启用归档、MMX 辅助、pelite 和 rand。以前只构建 `qlie` 的成功记录不能当成归档支持证据。
- `src/utils/mmx.rs:1` 起是纯 Rust 的打包整数运算；不能仅凭 MMX 名字断定必须运行 x86 指令。本轮真正的 ARM64 编译结果另行记录。
- `src/scripts/qlie/archive/pack/mod.rs:164` 起的构造器、后续 `iter_archive_filename` / `open_file` 是公开读取接口。适配器只调用这些接口，未调用写包或提取到目录的接口。
- 同文件读取目录字段；`open_file` 完成解混淆和按标志解压，并额外读取一个副本的短头进行类型探测。没有因此认定其已校验全部条目 hash 或所有解码长度。
- `pack/encryption.rs:931–972` 默认查找邻近 `key.fkey` 和 EXE 资源。本轮直接传入空的来源文件名，使该分支在 `is_file` 条件处退出；不向库提供原目录路径，不读取或运行邻近 EXE。
- `pack/encryption.rs:578–692` 的 BPE 解压器在 `Read` 返回前，将整块结果放入内部 Vec；声明解压大小未被用于强制限额。外层 `take` 不是内部内存上限，此缺口不能隐藏。

本轮所有游戏包均有受限尺寸、未压缩、方法 1 的嵌入密钥项。研究适配器仅接受这个已知配置；密钥仅在上游库的进程内存中使用，未导出、打印或写入报告。样本资源使用方法 2。没有提供通用整包提取或重新打包命令。

## 新的研究适配器

`tools/rust_archive_probe.rs` 仅包装上游 API，没有重写 PACK 算法。`tools/gpl_archive_probe.py` 负责来源核对、构建、输入约束和结果比较：

1. 按锁定源码和 Cargo.lock，关闭默认功能，仅构建 `qlie-arc` 库。自写适配器链接这次构建实际产出的 rlib；编译包元数据和日志保留在私有目录。
2. 逐个组件以 `O_NOFOLLOW`、只读方式打开原包；文件大小及 SHA-256 必须符合冻结 P0 清单。传给子进程的只有此只读文件描述符。
3. 只允许读取目录/尾部、受限嵌入密钥项和既有 P0 选定资源的区间。子进程拒绝区间外读取、越界 seek、过量读和过多 seek；不通过资源名打开任何输出路径。
4. 子进程仅将选定资源的有界字节流送入本机私有管道。Python 父进程计算 SHA-256 并丢弃字节，不保存新的商业资源副本，也不把资源正文送入日志或外部服务。
5. 目录名称按完整顺序与 P0 索引比较；每个样本均先核对已有合法研究副本的摘要，再比较新解码结果。原包结束后再次计算 SHA-256。

报告为每个选定资源保存原包相对路径、源摘要、offset、length、存储字节范围摘要，以及对应研究副本的引用。不同包中的版本全部保留，未选择“最新包”为最终运行版本。

尺寸和时间边界：单项输出 16 MiB、每包累计输出 128 MiB、子进程原包读取 64 MiB、seek 100 万次、CPU 30 秒、墙钟 40 秒；禁止子进程写普通文件和生成 core dump。**没有建立硬 RSS 上限，BPE 内部块分配限额仍为 `unsupported`**。因此本轮只接受冻结摘要的已知输入，不是对任意导入包的安全承诺。

完整检查记录在 `round25-tests.json` / `round25-readiness.json`：系统 Python 336 项通过、3 项跳过，研究 Python 339 项通过、零跳过；既有 qlie-unpack 合成上游测试 26 项通过、8 项缺少商业 fixture 跳过。这里的 26 项不能当成 GPL Rust 库的测试覆盖；本轮未运行 msg-tool 的完整上游归档测试套件，相关覆盖为 `not_tested`。跳过均未计入通过。20 个关键原文件摘要复核通过，冻结 P0 相对本轮起始快照也保持一致。

此前“没有本机验证过、许可明确的归档候选”的缺口已缩小：现在至少有这一固定 GPL 库的真实读取结果。**正式后端仍未完成**，主要剩余问题包括内部解压内存边界、完整输入校验、全部条目校验值、错误恢复和正式分发方案。

## 许可证与运行时边界

GPL-3.0-or-later 的证据是该固定 commit 的 Cargo.toml 和 LICENSE。68 个本轮编译包的许可字段是各包元数据声明，没有把它当成完整法律审查。生成的库和适配器二进制仅在忽略目录，本轮没有分发。

本轮不决定整个项目采用何种许可证，也不声称独立进程能豁免 GPL 义务。后续可以评估遵守适用 GPL 条件的组合方案，或寻找获得合适授权的其他实现；不能自动把技术验证成功转成发布许可。相关约束见 `AGENTS.md` 和 `THIRD_PARTY.md`。

Rust 在这里是现有候选库的实现语言，不构成整个运行时必须采用 Rust 的结论。研究父进程用 Python，也不意味着最终应用必须依赖 Python。没有将当前无许可证 Python 解析器打包进原生应用。

## 复现

需要既有固定上游源码、Rust 工具链，以及用户合法持有的原目录和此前有界研究副本：

```sh
.venv/bin/python tools/gpl_archive_probe.py \
  --game-dir "$GAME_DIR" --assets-dir "$ASSETS_DIR"
.venv/bin/python tools/research_checks.py --game-dir "$GAME_DIR" --stage round25 \
  --artifact reports/p1/gpl-archive-build.json \
  --artifact reports/p1/gpl-archive-report.json
```

该命令会重新核对源码、按锁构建库和适配器、运行 Rust 自建测试、比较相同样本，并生成脱敏报告。不会更新冻结 P0。失败、缺失、上游警告、panic、摘要或管道不一致均不会计作成功；完整私有进度及构建日志留在 `private/p1-round25/`。

下一阶段应先补资源导入边界及异常样本验证，再考虑是否将后端接入应用。当前静态工作约束下，不在本轮实现这些应用功能。脚本完整执行、演出、音频同步、分支和存档仍是整作移植的大量剩余工作。
