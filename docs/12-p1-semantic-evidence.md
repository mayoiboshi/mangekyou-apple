# 12 — P1 第二轮：结构约束、补丁差异与存档边界

2026-11-07。本轮继续第四作的静态研究；全作原生移植尚未完成。`round2-readiness.json.status` 仅表示这一轮取证及复验通过，不能解释为 P1 全部完成或游戏可运行。

## 剧本结构约束

输入为前一轮的 379 份 `.s` / `.txt` 研究副本及逐字节词法 IR。`tools/semantic_evidence.py:load_documents` 重新检查文件 SHA-256、每条记录的偏移、长度、记录摘要与整体字节覆盖。没有执行表达式、展开宏或选择某个包版本。

显式候选语法为：将 `if`、`for`、`case` 压入同一个嵌套栈，将 `end` 配对出栈；`then` 要求栈顶是 `if`。这只是待验证的语法模型。379 份文件都符合此模型，配成 2,639 个块：`if` 2,137、`for` 377、`case` 125，最大深度 4。事实来自 `contract-report.json.block_hypothesis`；模型本身仍为 `inferred`。

不能丢弃的例外包括：

- 16 个 `if` 没有 `then`；不能规定所有条件块都必须出现 `then`。
- 8 个 `for` 没有参数；不能直接报错或自行赋予无限循环语义。
- `ret` 有 1,910 条零参数记录，以及两条一参数记录。后两条来自同一个逻辑脚本的两个包副本，并非两个独立机制样本：`data7.pack/avg/avgsystem_select.s` 的 offset 1130、`data8.pack/avg/avgsystem_select.s` 的 offset 2262。完整来源摘要见私有 contract 报告。
- 所有回斜线命令候选共有 245 种，最长 4 字符；这不包含其他行首标记，不等于全部引擎指令数量。

变量共找到 4,041 个声明名称样式，不能因为命令叫 `var` 就只支持整数。真实类型拼写还包括字符串、列表、表、对象，以及多种图像/按钮/媒体对象。`gvar` 的类型种类比 `svar` 更多；类别和类型不能合并成一个枚举。具体计数见 `declaration_type_counts`。

共记录 4,761 个赋值目标候选、6,549 个参数/结果寄存器词法出现位置、550 个标签区域的参数足迹，以及 4,261 个转移命令样式。参数足迹只说明某个下标在源码中出现，**不是可接受参数数量、读写方向或调用约定**。

## 补丁差异

`patch-impact-report.json` 对前一轮的 11 组实质文本差异建立了变更行范围、原始字节范围、范围摘要、最近标签、命令计数及声明/赋值候选。它保持每个包来源；不使用文件名或排序决定加载赢家。

即使两个副本的命令序列相同，参数或文本也可能变化。当前结果只证明变更位置，不证明它在运行中生效，也不把提供目录认证为纯净日文发行版。加载优先级仍为 `not_tested`。

## 存档边界

对启动、变量定义和存读档相关的脚本名称区域，找到 300 个候选操作；记录同一行的对象选择器及参数摘要。选择器不会跨行推定持久性；操作名称本身不证明保存/加载语义。

目录中的 `补丁/存档/SystemData.dat` 为附带的存档候选，而非本次运行生成的样本。已只读核对其大小、SHA-256、前四字节和 offset 12 的 `IMOSYSDATA12` 标签；没有解密、恢复或写入存档。`cndata.dat` 不因扩展名被视为存档。见 `save-boundary-report.json.save_header_candidates` 和 `excluded_dat_files`。

系统变量的声明位置可以定位，但其持久化、槽位格式、缩略图、脚本恢复点、对象状态、演出时间线和原版存档兼容均未验证。

### 读取器恢复位置

`verified`（同一原版 EXE，LLVM 静态指令窗口）。`0x6957a5` 将读取器记录的版本设为 10。随后两个助手分别取当前位置的相对行和行内位置，填入记录，再由 `0x6957cc` 的流接口虚调用接收 77 字节。`0x6958dc` 至 `0x6958e8` 的反向路径将同样大小的数据传入读取器记录。这证明了记录在读取器流接口上的边界，尚未验证外层槽文件的封装。

`0x695a29` 返回后，`0x695a31`–`0x695a41` 将记录中的行内位置和相对行传给 `0x696134`。该助手查找标签，查找失败直接返回零。成功时，它将标签所在行加上相对行，并把结果与保存的行内位置一起交给 `0x69630c`。保存侧的 `0x6961bc`–`0x6961eb` 对应地从绝对行减去标签所在行，并直接取得行内位置。恢复点因此需要关联脚本、标签、相对行及行内位置。

`verified`（同一原版 EXE，读取器位置单位）。`0x6963c6`–`0x6963d9` 将行号和位置写入读取器的 `+0x38`、`+0x3c`，并取出对应行。缓冲区写入前，常规分支执行替换和前缀处理（`0x6963eb`、`0x6963f5`、`0x6964eb`）；另有分支直接保留取得的行。`0x695aec`–`0x695b13` 从 `+0x3c` 取游标，以两倍游标为地址偏移读取 16 位单元，每次加一，并在 `0x695b40` 回写游标。因此保存的是读取器当前行缓冲区的零基 UTF-16 代码单元位置。原始脚本中的对应位置取决于处理分支及当时的替换状态。跨版本标签变更和用真实存档恢复仍为 `not_tested`。

`verified`（替换规则的加载顺序）。`0x69598a–0x695a03` 读取规则数，依次读入两条字符串和一个四字节字段，将记录加入读取器 `+0x34` 的列表。此循环先于 `0x695a29` 重开脚本和 `0x695a41` 恢复游标。原生预检已校验这些字符串和读取器文本的 UTF-16 编码。变换结果到原字节的映射仍为 `not_tested`。 `0x695d12` 检查替换开关，`0x695d55` 读取规则模式，模式 0 路径在 `0x695d85–0x695d8a` 使用规则的两条字符串。隔离恢复仅接入不重复的模式 0 行标签规则，真实脚本搭配人工构造的规则验证了回调分派，原版规则与通用替换顺序的运行等价仍为 `not_tested`。 后续将第四作脚本中实际注册的规则装入合成槽位，验证 `isolatedContinuation` 中的 `line_tag_replacement_call_candidate`。合成的 `Avg_SceneSkipFlag=1` 使回调返回并抵达点击等待，设为 0 则抵达 `draw` 边界。规则来自脚本，槽位与分支变量值为人工构造。

### 槽位查询与加载分派

`verified`（同一原版 EXE，LLVM 静态指令窗口）。`0x6b3fe2`–`0x6b403a` 的分派比较值把 `l`（0x6c）送到 `0x6b4045`，把 `?g`（0x673f）和 `g`（0x67）送到 `0x6b419c`。这与真实读档脚本的查询及加载路径对应。

`verified`（对象数组的附加读取入口）。对象数组的 VMT `0x697ce0` 在 `+0x14` 指向 `0x69e60c`。逐元素读取字符串后，`0x69e69b–0x69e6bf` 仅在对象 `+0x18` 为零且回调槽存在时，将流和元素文本等参数交给回调。初始化时的 ObjectLoad 候选 `0x6bef28` 先调用 `0x6befa8` 取得对象，再通过其 VMT `+0x0c` 消费同一状态流，并尝试向宿主容器登记对象（`0x6bef4c–0x6bef70`）。因此存在字符串之后还需读取类专用正文的路径。实际类映射和回调运行时绑定仍为 `not_tested`，目前解析器继续拒绝无法确定长度的对象正文。

`verified`（构造分派的前九个比较项）。`0x6befdd–0x6bf146` 比较的 UTF-16 常量依序为 `img`、`msg`、`btn`、`bar`、`simg`、`sbtn`、`file`、`list`、`table`。`list` 分支调用 `0x68e2a4`，其 VMT `0x688764` 的加载槽 `+0x0c` 指向 `0x68e3cc`。`table` 分支调用 `0x68f1e8`，对应 VMT `0x6889b4` 的同一槽指向 `0x68f308`。这定位了可与原生列表、表对象对照的两个读取器，正文结构和真实槽中的出现情况仍为 `not_tested`。

`verified`（同一原版 EXE，末尾读取与恢复完成顺序）。`0x6ae122` 调用末尾对象读取器，`0x6ae129–0x6ae149` 随后从同一状态流读取八个字符串，依次写入宿主对象 `+0x2f8 + 4*i`。保存侧 `0x6ae4ff–0x6ae513` 从同一数组按同序写出。另有两条脚本分派路径写入这个数组，`0x6b2e08–0x6b2e48` 批量写槽 0 至 6，`0x6b2e9a–0x6b2ebb` 校验单项索引后写入。分派比较值 `0x6e` 和 `0x326e`（`0x6b29e9–0x6b29ee`、`0x6b2a53–0x6b2a58`）分别对应 `sys n` 和 `sys n2`。第四作保存脚本在 `script/saveload/main_save.s:47` 调用 `n2` 更新槽 3。原生端在读档候选状态中暂存槽 0 至 6，第八个字符串仍只保留边界。

`verified`（同一原版 EXE，成功标志前的清零操作）。`0x6ae14b–0x6ae1be` 对五个状态字段应用小于 1 时的默认值，并调用两个后处理函数。`0x6ae1c5` 调用的 `0x6b9c54–0x6b9c73` 仅把宿主 `+0x2ac` 与全局对象 `+0x870`、`+0x871` 三个字节清零，随后返回。调用者释放槽对象才设置成功标志。三项状态的原生对应关系及另外两个后处理函数的语义仍为 `not_tested`。

`verified`（用户提供的第四作安装目录）。`SaveData/SavePath.txt` 为带 BOM 的 UTF-16LE 文件。跳过注释后，活动的 `SavePath` 以 `<MYDOCUMENTS>` 开头，指向 Windows 用户的 Documents 目录下的游戏专用子目录。安装目录的 `SaveData` 没有剧情槽，补丁附带的 `SystemData.dat` 通过 Swift 外层校验并识别为系统数据。原生检查接受显式的只读槽位目录，便于核对另行提供的 Windows 存档副本。

`not_tested`（Windows 目录展开及真实剧情槽）。当前只检查了安装目录及本机 Documents、Downloads 下同名目录的有限层级。原版的 Windows 特殊目录展开和实际槽位恢复仍未验证。

## 测试和复现

新增测试只含自造文本和最小 PE 字节，见 `tests/test_semantic_evidence.py`：嵌套/失配块、零参数循环和带参数返回的保留、引号内寄存器排除、动态下标摘要、UTF-16 字节位置、IR 篡改拒绝、选择器行边界、公开报告脱敏，以及原生取证的身份和操作白名单。

完整研究环境当前为 85 项通过；系统 Python 运行 85 项，其中 82 项通过、3 项可选图像相关检查跳过。跳过不算通过。上游套件另有 34 项，26 项通过、8 项商业夹具相关检查跳过。实际结果见 `round2-tests.json`；这些测试不证明游戏执行语义。

已有 P1 研究副本和原生证据时：

```sh
.venv/bin/python tools/reproduce_p1_round2.py \
  --game-dir "$GAME_DIR" --exe "$GAME_EXE_REL"
```

`GAME_EXE_REL` 是相对游戏目录的主程序候选路径。该命令只读检查 EXE，重新生成结构/差异/存档边界和原生摘要，运行两套本项目测试及上游验证，最后核对原始关键文件和 P0 报告摘要。原生证据从零生成的命令见第 13 篇。

完整 IR、反编译输出、汇编和工具日志仅在忽略的 `private/p1-round2/`。公开报告没有台词、完整参数、密钥或程序代码。`verify_upstream.py` 的默认输出已改到 `private/upstream-verification.json`，后续验证不会默认覆盖 P0 历史报告。

### 读档后的文件日志

第四作主程序的 `0x5b18f0` 将存档里的字符串列表载入文件日志对象的 `+0x08`。整数查询 `0x5b18c4 → 0x5b1444` 则通过 `+0x04` 的后端读取四字节值，查询失败返回 `-1`。这两条访问路径在静态分析中可区分。隔离续跑沿用会话的整数映射，写入仍只发生于隔离副本。后端持久化和键比较规则尚未验证。`0x4e133f–0x4e1367` 接受列表数量 `-1` 并读取零条记录，现有合成边界测试覆盖此值。

### 上部菜单按钮数组的读档边界

真实 data8 脚本在 `avg/uppermenu/layout.s:10` 声明三个 `sbtn`，`avg/uppermenu/main.s:26` 用 `garr` 查询同一数组。当前合成槽只包含标量，故隔离回放停在 `garr_requires_button_array`。本次提供的原版目录没有找到 `.svd` 文件，不能用该停点反推原版存档必然以何种形式保存按钮。

原版对象构造分派在 `0x6bf0c7–0x6bf0e9` 为 `sbtn` 调用 `0x68cd28`。类指针 `0x688398` 指向 VMT `0x6883f0`，其加载槽 `+0x0c` 指向 `0x68c744`。该读取器先调用基础对象读取 `0x68bd54`，再把内部按钮对象 `+0x18` 交给 `0x67c698`。后者先调用 `0x678d5c`，再从输入流读取 42 字节至按钮对象 `+0xf00`。因此带内嵌载荷的按钮记录需要独立读取器，不能沿用列表或表对象布局。引用重绑定与完整载荷边界仍待核对。

内部读取器 `0x678d5c` 先在 `0x678dc9` 调用已有图像库读取器 `0x5abb34`，随后在 `0x678ddd` 读取 189 字节固定记录。接下来的五次 `0x4e0e04` 调用（`0x678ded–0x678e48`）读取长度前缀字符串。版本小于 11 的分支改变固定记录字段的使用方式，未增加流读取。`0x67c698` 在这段之后附加 42 字节固定记录。后续解析应复用图像库边界检查，并分别保留两段固定记录和五个字符串的字节范围。按钮资源加载和事件回调仍需独立取证。

当前隔离续跑只为具有完整内嵌载荷、且无引用名的全局 `sbtn` 数组分配对象标识。合成存档加入三个这样的元素后，第四作真实脚本在第 128 步完成 `garr`。报告用 `stagedGlobalButtonIdentityArrayCount` 单独记录此类数组。该标识仅供隔离计算，不恢复按钮绘制、状态、事件或跨对象引用。

合成槽补齐 `avg/avgsystem_sceneskip.s:13–15` 声明的整数和字符串后，真实脚本越过第 19 行的赋值，隔离回放推进到 181 步。下一条为 `misc/misc.s:491` 在 `sys` 作用域执行 `?p`。普通执行从系统播放模式读取，隔离存档状态尚未确认该值来源，因此仍在该指令前停止。

`sys ?p` 在 `0x6b23dd` 读取实例 `+0x2ac`。成功读档在 `0x6ae1c3–0x6ae1c5` 将读档实例传给 `0x6b9c54`，后者将同一字节清零。隔离续跑在通过存档尾部结构检查后应用此重置，并允许系统作用域中的 `?p`。真实脚本搭配合成槽已执行该查询。

系统锁在 `0x6ae017–0x6ae027` 载入的 419 字节区段内。原版把区段写入实例 `+0x14c`，`?lk/?lkc` 分别读取 `+0x158/+0x15c`，因此两个值在该区段的偏移为 12、16。隔离回放从已解析区段恢复两个有符号 32 位掩码，并支持系统作用域内的查询和写入。合成槽用不同的非零掩码验证了解码，真实脚本执行了查询和两个写入命令。

影片入口 `avg/avgsystem_movie.s:114` 在 `eff` 作用域执行无参 `c`。`0x6b60b5–0x6b610a` 用默认优先级 60000 调用实例 `+0x124` 的效果对象，读档也在 `0x6adfd2–0x6adfd8` 恢复同一对象。`0x693716–0x693727` 在全局 `+0x872` 非零或效果模式为 1 时跳过重新捕获。其余情况下，默认优先级进入 `0x693735–0x693762` 的黑色填充路径。当前隔离回放尚未恢复该效果对象和宿主标志，单独报告 `saved_effect_capture_requires_restored_state`。
