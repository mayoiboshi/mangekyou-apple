# 06 — P1 建议与路线比较

本篇保留 P0 结束时的建议。后续用户明确授权完整应用开发；当前已进入原生基础阶段，范围、实际产物与未决项见 `docs/31-native-app-foundation.md`。该授权不改变本篇对语义、许可和等价验证风险的判断。

**建议进入限定的 P1：真实语料整理、包覆盖规则及脚本语义取证。暂不进入播放器、应用界面或完整解释器开发。** 原因是资源访问已由真实数据证明可行，主要未知已经转为脚本行为、系统状态和演出语义。

| 路线 | 兼容性 / 还原 | 工程复杂度 | 原生化 / 跨平台 | 维护与最大阻塞 |
|---|---|---|---|---|
| A 复用 QLIE 兼容运行时 | 未找到具有第四作实证的候选；不能认为一定不存在 | 找到候选前无法估计 | 未验证 | 四个优先工具及 GARbro 都不是已验证的兼容运行时；许可与命令覆盖未知 |
| B 本作专用解释器 | 取决于真实命令、宏、存档与时间线覆盖 | 高；即使只支持一作也不能跳过系统脚本 | 可设计原生核心及平台接口 | 自行承担语义与回归，当前证据不足以实现执行器 |
| C 无损 IR 再执行 | 利于追溯，不能填补未知语义 | 高；转换器和执行器均需验证 | 未来跨平台潜力较好 | 过早将命令归一化可能丢失行为；先做保留字节来源的词法 IR |
| D Wine/CrossOver 原引擎对照 | 若能运行，可能提供演出参照；本作未测试 | 初期可能较低（inferred） | 不满足原生游戏核心目标 | 依赖原 EXE 与兼容层；仅后备/对照，不作为最终必要组件 |

A 的结论仅限已调查候选和公开搜索，不是对所有开源项目的不存在证明。[GARbro](https://github.com/morkt/GARbro) 自述是资源浏览/提取工具，不能作为脚本运行时。官方 QLIE 网站本次无法访问，没有据此推断其当前许可或运行时提供方式。[CrossOver 官方指南](https://support.codeweavers.com/en_US/crossover-mac-user-guide) 说明 Apple Silicon 支持，但不证明本作可运行，也不能代替 P0 的禁止执行要求。

当前推荐 B/C 的共同前置工作，倾向保留 C 的**无损取证 IR**，不先承诺转换为某个既有视觉小说语言。若动态宏和表达式使预转换难以保持行为，则 B 的直接解释更合理；若大多数结构可静态解析且转换等价可测试，再决定 C 的可执行 IR。

P1 的合理交付范围：

1. 固定当前输入摘要，并与用户另行提供的干净版区分；记录每个逻辑路径的所有包版本，不预设覆盖顺序。
2. 对 283 份 `.s` 与 96 份 `.txt` 建立角色、编码、宏/include、标签和命令目录。逐项关联原始文件、offset、字段摘要和证据等级。
3. 用显式 Qlie 模式提取并交叉核对实际文本；查明注释、姓名和选择项的例外，不能把通用 text_candidate 当真实台词。
4. 解析可证明的参数语法和定义/引用关系；未知标记、表达式或动态资源引用保留 Unknown。先获得调用/分支/变量的证据，再设计执行状态。
5. 对 ABMP12 内部和 DPNG 半透明重叠补足代表样本；扩大媒体/资源验证，并解决第三方许可复用边界。
6. 输出“已确认 / 假设 / 未支持”的命令语义表、资源歧义列表、格式变体测试集及下一阶段准入条件。回归样本仍使用合成数据，商业样本只保存在本机。

P1 不需要界面、音画播放、完整存档支持或纯台词顺播演示。后续若要执行原引擎采集对照，属于新的明确工作范围，本次不执行。

语言暂不定：Python 适合当前调查；C++ 可复用部分媒体生态，Rust 可提供跨平台核心边界，Swift 可便利接入 macOS，但各自都不能解决未知语义。待确定解释模型、媒体/字体依赖、热路径和许可后，再用小型等价测试与原生构建比较，而不是先以语言偏好决定路线。
